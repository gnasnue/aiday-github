# Land and Deploy — 머지 및 배포

열린 PR을 main에 머지하고 배포가 정상인지 확인한다.

## 진행 순서

1. **머지 전 확인**:
   - PR의 CI/체크 상태가 모두 green인지 확인
   - main과의 충돌 여부 확인 — 충돌이 있으면 브랜치를 최신 main 위로 정리 후 재푸시
   - CHANGELOG.md·VERSION·`package.json` 버전이 이번 릴리스에 맞게 올라가 있는지 확인 (누락 시 /ship 절차로 보완)
2. **머지**: 사용자에게 최종 확인을 받은 뒤 머지한다. 머지는 되돌리기 어려운 동작이므로 확인 없이 진행하지 않는다.
3. **배포 확인**:
   - 배포 파이프라인(Vercel 연동 시 Vercel 배포 상태, 그 외 호스팅은 해당 대시보드)이 성공했는지 확인
   - 배포된 사이트에서 핵심 경로 스모크 테스트: 랜딩 → 로그인 → 홈 AI 리포트 표시
4. **마무리**: 머지된 feature 브랜치 삭제, 릴리스 요약 보고.

## 규칙

- 배포 실패나 스모크 테스트 실패 시 즉시 보고하고, 롤백 여부는 사용자 판단에 맡긴다.
- 환경 변수 추가가 필요한 릴리스면 배포 환경에 반영되었는지 반드시 확인한다 (`.env.example` 대조).
