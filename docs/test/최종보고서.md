## 4. 발견된 주요 버그 (2건)

1. **BUG-1 — 데모 프로필 "예시" 배지 미표시.** PRD S-001은 데모 프로필에 `(예시)` 표기를 요구하나, `lib/profile.ts`의 판별 함수 `isDemoProfile`을 참조하는 렌더링 코드가 전무해(grep 확인) 화면에 전혀 표시되지 않는다. 실 API 1회 + 모킹 회귀 재현 2회(mobile/desktop)로 3회 모두 확인.
2. **BUG-2 — 게스트 429 화면에 회원가입 유도 문구·CTA 없음.** PRD는 게스트/로그인 429를 다른 문구로 요구하지만, 실제로는 서버가 동일 메시지를 반환하고 클라이언트는 이를 일회성 토스트로만 표시해 게스트 전용 전환 유도(가입하면 계속 이용 + [무료로 시작하기])가 전혀 없다. 서비스가 빈 화면이 되지는 않는다(규칙 기반 콘텐츠 정상 표시).

두 건 모두 크래시·데이터 손실·보안 문제가 아닌 **UX/전환 최적화 격차**이며, 재현 절차·스크린샷·트레이스는 `test-report.md` §⑦·⑨에 상세 기록했다.

## 5. 배포 가능 여부: **CONDITIONALLY READY**

로그인/세션·권한(비로그인 라우트 접근)·핵심 데이터 등록(온보딩)·핵심 업무 완료(AI 브리핑)·저장 결과 반영(프로필 편집) 등 **P0 핵심 기능은 모두 실제로 정상 작동**하며, 레이트리밋의 안전장치(429 임계값·폴백)도 정확하다. 다만 PRD가 명시한 게스트 전환 유도 UX(BUG-2)와 데모 배지 표시(BUG-1)가 코드에 구현되어 있지 않아 READY로 판정하지 않았다. 두 건 다 배포를 막을 정도의 심각도는 아니므로, 수정 후 배포와 다음 스프린트 이연 둘 다 합리적 선택지이며 최종 판단은 제품 오너 몫이다.

## 7. 수정 및 재검증 결과 (2026-07-24)

**수정 내역:**
- **BUG-1** — [app/(main)/home/page.tsx](app/(main)/home/page.tsx): `isDemoProfile` 배지 렌더 추가.
- **BUG-2** — [app/api/report/route.ts](app/api/report/route.ts) `isGuest` 플래그 + [app/(main)/home/page.tsx](app/(main)/home/page.tsx) `reportLimitReached` 영구 배너(게스트 전용 "무료로 시작하기" CTA 포함)로 게스트/로그인 429 문구 분기.
- 부수적으로 `vitest.config.ts`(e2e 스펙과 vitest 충돌 제외), `playwright.config.ts`(로컬 검증용 `E2E_BASE_URL`), `tests/e2e/09-rate-limit.spec.ts`·`fixtures.ts`(재검증 중 발견한 테스트 코드 타이밍 경합·strict-mode 충돌 수정)도 함께 정리.

**재검증 방법:** 수정은 아직 배포 전이라 라이브 데모로는 확인할 수 없어, **로컬 dev 서버**(`npm run dev` + `E2E_BASE_URL=http://localhost:3000`)로 재실행했다. `npm run build`·`npm run lint`·`npm test`(vitest, 261 passed) 전체 통과 확인 후, BUG-1·BUG-2 관련 모킹 회귀 테스트(실 Claude 비용 없음)와 TC-AUTH-05를 재실행해 모두 PASS 확인했고, 회귀 점검으로 비용 없는 스펙 43건을 추가 실행해 42 PASS·1 FAIL(로컬 `next dev` 전용 Dev Tools 오버레이 아티팩트 — 프로덕션엔 없음, 앱 버그 아님)을 확인했다.

**최신 카운트:** 총 56 테스트(TC-AUTH-05 자동화로 +1) · 통과 55 · **실패 0** · BLOCKED 1(Google OAuth, 수정 불가 — 외부 계정 필요) · N/A 3(PRD 미구현, 범위 밖).
