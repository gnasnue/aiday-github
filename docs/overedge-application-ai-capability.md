## 상세 서술 (2p 분량 — A4 기준)

### 1. AI를 현재까지 활용한 내용

#### 1-1. AI-Native 개발 방식 — AI Agent를 팀으로 운용

aiday는 창업자 1인이 개발했지만, 실제 의사결정과 품질 관리는 gstack(Claude Code 기반 멀티 에이전트 프레임워크)의 전문 AI Agent들이 수행했습니다. 각 Agent는 독립된 역할을 맡아 실제 팀과 동일한 방식으로 작동했습니다.

| Agent 역할 | 활용 스킬 | 실제 수행 내용 |
|-----------|-----------|--------------|
| CEO (제품 전략) | `/plan-ceo-review` | SSE 스트리밍 vs. 블로킹 JSON 아키텍처 선택. 리스크 매트릭스 작성, Approach A(블로킹 JSON) 채택 결정 |
| CTO (기술 검토) | `/plan-eng-review` | API 이중 호출 버그 발견, try/catch 누락 지적, 에러 전파 설계 리뷰 |
| 디자이너 | `/design-review` | DESIGN.md 기준 감사: BottomNav 이모지→Lucide 아이콘 교체(FINDING-001), 터치 타겟 32px→44px 수정(FINDING-002), 랜딩 이모지 제거(FINDING-003) |

각 리뷰 결과는 `docs/reviews/` 디렉터리에 마크다운 문서로 커밋되어, 의사결정 근거가 Git 히스토리로 추적됩니다. 이는 AI Agent가 단순 코드 자동완성 수준을 넘어, **실제 스타트업의 실행 조직으로 기능했음**을 보여줍니다.

#### 1-2. Harness Engineering — 프로덕션 AI 출력 안정화

Claude Haiku API를 통해 매일 아침 맞춤형 육아 리포트를 생성하는 `/api/report` 엔드포인트를 구축했습니다. AI 출력을 프로덕션에서 신뢰할 수 있는 형태로 사용하기 위해 다음의 Harness Engineering 기법을 적용했습니다.

```
[입력 스키마 강제]
  시스템 프롬프트에 JSON 출력 형식 명시
  { message: string, checklist: string[] }

[출력 파싱 폴백]
  JSON.parse 실패 시 → 정규식으로 배열 추출 시도
  추출 실패 시 → 기본 체크리스트 반환 (앱 크래시 방지)

[온도 제어]
  temperature: 1.2 → 1.0 (Anthropic API 허용 범위 초과 오류 수정)
  낮은 온도로 출력 일관성 확보
```

SSE 스트리밍 방식에서 블로킹 JSON 방식으로 전환한 것도 Harness Engineering의 일환입니다. Next.js 15 환경에서 스트리밍은 파싱 복잡도를 높이고 에러 추적이 어려웠으므로, CEO Review Agent의 권고를 수용해 단일 JSON 응답으로 단순화했습니다. 이 결정은 `docs/reviews/2026-06-10-ceo-review-ai-report.md`에 아키텍처 다이어그램과 함께 기록되어 있습니다.

#### 1-3. 현재 기술 스택 요약

- **AI**: Claude Haiku API (`@anthropic-ai/sdk`) — 개인화 육아 리포트
- **규칙 엔진**: `lib/recommendation-engine.ts` — 아동 프로필 × 환경 데이터 기반 체크리스트 생성 (AI와 병렬 운용)
- **공공 API**: 기상청 단기예보·UV지수·꽃가루농도, 에어코리아 대기질
- **배포**: Next.js 15 + Vercel, MVP 배포 완료 (https://aiday-demo.vercel.app/)
- **개발 방법론**: AI-Native (AI Agent 팀 운용), Harness Engineering (AI 출력 제어)

### 2. AI를 앞으로 활용할 계획

aiday의 핵심 비전은 **AI Agent가 1인 창업자의 실행력을 팀 수준으로 확장하는 것**입니다. 현재 AI Agent는 개발 프로세스(리뷰·설계)에 활용되고 있으나, 앞으로는 **서비스 가치 사슬 전체**로 확장할 계획입니다.

#### Phase 1 — 콘텐츠 파이프라인 자동화 (3개월)

건강팁 콘텐츠를 지속적으로 최신화하기 위해 AI Agent 파이프라인을 구축합니다.

```
공공 지침 업데이트 감지 (에어코리아, 질병관리청)
       ↓
AI Agent: 변경 사항 파싱 및 임계값 추출
       ↓
Harness: JSON 스키마 검증 → DB 반영
       ↓
건강팁 규칙 엔진 자동 갱신
```

현재 에어코리아 행동요령(PM2.5/PM10 민감군 기준)을 수동 코딩했으나, 이를 AI Agent가 정기적으로 크롤링·파싱·구조화하는 자동 파이프라인으로 대체합니다. 약 ~50개 임계값 규칙의 유지보수 비용을 제로에 가깝게 낮춥니다.

#### Phase 2 — 개인화 심화 (6개월)

현재 AI 리포트는 아동 프로필(나이, 알레르기, 비염 여부)과 당일 환경 데이터를 조합해 생성됩니다. 이를 **행동 데이터 피드백 루프**로 확장합니다.

- 학부모가 체크리스트 항목을 완료/건너뜀 → 행동 로그 수집
- AI Agent가 패턴 분석 → 개인별 가중치 조정
- 반복적으로 무시되는 팁은 빈도 조정, 자주 완료되는 팁은 강화

이 구조는 Harness Engineering의 확장입니다 — AI 출력을 단순히 안정화하는 것을 넘어, **출력이 현실 행동에 미치는 영향을 측정하고 개선하는 루프**를 만듭니다.

#### Phase 3 — AI Agent 운영팀 고도화 (12개월)

현재 gstack Agent는 개발 단계에서만 활용됩니다. 장기적으로는 **서비스 운영 전반**을 AI Agent로 자동화합니다.

| 운영 영역 | AI Agent 역할 |
|---------|--------------|
| 사용자 피드백 분석 | 앱스토어 리뷰·인앱 피드백 주간 요약 및 우선순위화 |
| A/B 테스트 설계 | 가설 수립 → 실험 설계 → 결과 해석 자동화 |
| 의학 콘텐츠 감수 | 공개 임상 가이드라인 변경 시 팁 내용 정합성 검토 |
| 투자자 업데이트 | KPI 데이터 → 월간 리포트 자동 생성 |

**핵심 메시지**: aiday는 AI를 기능으로 추가한 앱이 아니라, AI Agent를 팀원으로, Harness Engineering을 품질 기반으로 삼아 처음부터 설계된 AI-Native 스타트업입니다. OverEdge 프로그램을 통해 이 방법론을 실제 창업 환경에서 검증하고, 1인 창업자가 AI를 레버리징해 팀 수준의 실행력을 갖출 수 있음을 증명하고자 합니다.
