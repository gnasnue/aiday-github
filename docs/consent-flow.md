# 개인정보 동의 절차 (Consent Flow)

> 최종 갱신: 2026-07-20 · 정책 버전 `2026-07-20-v3`
> 코드가 단일 진실. 이 문서는 요약이며, 문구·조건은 아래 "근거 파일"을 우선한다.

지인 베타(가입 마찰 최소화) 원칙에 따라 **선불 일괄 동의를 폐지**하고, 가치 경험 흐름에 맞춰 동의를 **맥락별로 분산**했다. 결정 근거는 [docs/reviews/2026-07-19-ceo-review-beta-consent-conversion.md](reviews/2026-07-19-ceo-review-beta-consent-conversion.md).

## 1. 동의 항목 (Consent Types)

정의: [lib/consent.ts](../lib/consent.ts)

| 항목 (`ConsentType`) | 필수/선택 | 수집 방식 | 근거 문서 |
|---|---|---|---|
| `terms_privacy` (이용약관·개인정보) | **필수** | 사용자가 직접 체크 | 이용약관 전문 + 개인정보처리방침 |
| `beta_analytics` (베타 이용기록·피드백 활용) | 번들(자동) | `terms_privacy` 체크 시 함께 기록 (`withBundledBetaAnalytics`) | 이용약관 §5, 개인정보처리방침 §3 |
| `sensitive_child_data` (아이 건강 민감정보) | 조건부 필수 | 건강 정보 입력 시 직접 체크 | 개인정보처리방침 §2 |
| `overseas_transfer` (국외 처리) | 미수집(고지형) | 별도 체크 없음 — 계약 이행 근거로 방침 공개 | 개인정보처리방침 §6 |
| `marketing` (마케팅 수신) | 미수집 | 베타에서 수집 중단 | — |

- **번들 설명**: 별도 "분석 동의" 프롬프트(구 리포트 하단 배너)를 없애기 위해, 약관 동의 하나에 베타 이용기록·피드백 활용을 포함해 기록한다. 고지는 이용약관 §5와 개인정보처리방침 §3이 담당한다.
- **국외 처리**: 개인정보 보호법 제28조의8에 따라 계약 이행에 필요한 처리위탁·보관으로 방침에 공개하며, 별도 체크박스를 두지 않는다.
- 동의 기록은 로컬(`localStorage: aiday:consents:v2`)에 먼저 저장되고, 로그인 사용자는 Supabase `user_consents` 테이블로 동기화된다 (`syncLocalConsentsToDb`).

## 2. 동의 수집 시점 (Flow)

```
랜딩 /
  │
  ├─▶ 회원가입 /signup ───────────── ① [필수] 이용약관 (+ beta_analytics 번들)
  │        │
  │   로그인 /login ──────────────── 동의 UI 없음 (Google 신규 포함)
  │        │
  │   인증 판단 /auth/landing ────── 동의 UI 없음 · 이력 DB 동기화만
  │        │
  │   온보딩 1/5 기본정보 ────────── 동의 없음
  │        │
  │   온보딩 2/5 건강정보 ────────── ② [조건부] 건강 민감정보
  │        │                          (+ 약관 미동의 경로면 이용약관도 노출)
  │        │
  │   온보딩 3~5 · 홈 /home ──────── 동의 UI 없음
  │        │
  └─▶ 마이 > 프로필 편집 ─────────── ③ [저장 시] 건강 민감정보 확인 다이얼로그
```

### 지점 ① 회원가입 (`/signup`)
- 근거: [app/signup/page.tsx](../app/signup/page.tsx), [components/ConsentFields.tsx](../components/ConsentFields.tsx) (`context="signup"`)
- **[필수] 이용약관** 체크 1개. 체크하지 않으면 "가입하기"·"Google 계정으로 계속" 모두 진행 불가.
- 체크 시 `terms_privacy` + `beta_analytics`가 함께 기록된다.
- 박스는 반투명(`bg-card/40`)·무그림자, 라벨·링크는 muted 톤 (유입 마찰 최소화, 2026-07-20).

### 지점 ② 온보딩 2단계 — 건강 정보 (`/onboarding`)
- 근거: [app/onboarding/page.tsx](../app/onboarding/page.tsx) (건강 항목 선택 아래 인라인 체크)
- **[선택] 아이 건강 정보 활용** — 색 강조 없는 캡션 톤 인라인 체크.
  - '해당없음' 외 건강 특이사항을 선택한 경우에만 **필수**로 검증한다 (`hasProfileConsent`). '해당없음'만 고르면 동의 없이 통과.
- **[필수] 이용약관** — **조건부 노출**. 가입 화면을 거치지 않아 약관 동의 기록이 없는 경로(로그인 페이지의 Google로 처음 진입한 신규 사용자)에만 함께 노출된다. 가입 → 온보딩 정상 경로에서는 약관을 두 번 묻지 않는다 (`termsAlreadyAgreed` 분기).

#### '먼저 둘러볼게요' 이탈 안내 팝업
- 온보딩에서 '먼저 둘러볼게요'를 누르면 즉시 이탈하지 않고 안내 다이얼로그를 띄운다 (붙잡는 게 아니라 가치·개인정보 취급 안내).
- 제목: **맞춤형 리포트에는 정보가 필요해요**
- 본문: 아이의 체질과 건강 정보를 입력하면 아이데이가 우리 아이 맞춤형으로 케어 가이드를 작성할 수 있어요. 입력한 정보는 맞춤 리포트에만 사용되니 안심하세요.
- 버튼: `이어서 입력하기`(닫고 계속) / `홈 둘러보기`(게스트 모드로 홈 이동). 톤 다운을 위해 '이어서 입력하기'는 solid 대신 tint(`bg-primary-tint text-accent`).

### 지점 ③ 마이 > 프로필 편집 (`/me/edit/[id]`)
- 근거: [app/me/edit/[id]/page.tsx](../app/me/edit/%5Bid%5D/page.tsx)
- 화면 자체에는 동의 UI 없음. **저장하기**를 누를 때 민감정보 동의 기록이 없으면 확인 다이얼로그가 1회 뜬다.
- 온보딩에서 건강 정보 동의 없이 지나온 사용자가 나중에 건강 정보를 입력하는 경로를 커버하는 안전망.

### 동의 UI가 없는 지점
- **`/auth/landing`**: 로컬 동의 이력을 계정 DB로 동기화만 한다 (별도 게이트 화면은 2026-07-20 제거).
- **홈 리포트 하단 (👍/👎)**: 사용자가 직접 제출하는 자발 피드백이라 동의 게이트 없이 전송 (`lib/analytics.ts: sendFeedback`).
- **`/terms`, `/privacy`**: 동의 수집이 아닌 고지 문서.

## 3. 동의문 전문 (Consent Copy)

### 3.1 화면 노출 문구

**① 회원가입 · 온보딩 · 프로필 편집 공용 체크 라벨** ([components/ConsentFields.tsx](../components/ConsentFields.tsx))

> **[필수]** [이용약관](../app/terms/page.tsx)에 동의합니다.

> **[선택]** 아이 건강 정보를 맞춤 리포트에 활용하는 데 동의합니다. [자세히](../app/privacy/page.tsx) (→ 개인정보처리방침 §2)

**③ 프로필 편집 저장 시 확인 다이얼로그** ([app/me/edit/[id]/page.tsx](../app/me/edit/%5Bid%5D/page.tsx))

> **아이 정보를 안전하게 활용할게요**
> 건강 관련 정보를 저장하기 전에 한 번만 확인해요.
> (이하 위 체크 라벨과 동일 · 버튼: 동의하고 저장하기 / 취소)

> ⚠️ 검토 필요: 이 다이얼로그는 두 항목을 모두 체크해야 저장 버튼이 활성화되지만(사실상 필수), 건강 정보 활용 라벨은 여전히 **[선택]**으로 표기된다. 라벨과 동작이 어긋난 상태 — [선택]→[필수] 정정 또는 라벨 제거 검토 대상.

### 3.2 이용약관 §5 「베타테스트 참여」 (`beta_analytics` 고지) — [app/terms/page.tsx](../app/terms/page.tsx)

> 베타 서비스는 완성 전 단계로 오류, 일시 중단, 데이터 지연 또는 기능 변경이 발생할 수 있습니다. 운영자는 별도 동의를 받은 이용 기록과 의견을 서비스 안정성·사용성 개선에 활용합니다. 이용자는 언제든 참여를 중단하고 동의를 철회하거나 데이터 삭제를 요청할 수 있습니다.
>
> 베타 기간에는 이용기록·피드백이 서비스 개선에 활용되고 베타 종료 후 90일 이내 삭제됩니다. 자세한 처리 내용은 개인정보처리방침에서 확인할 수 있습니다.

### 3.3 개인정보처리방침 §2 「아동 및 민감정보의 처리」 (`sensitive_child_data` 고지) — [app/privacy/page.tsx](../app/privacy/page.tsx)

> 알레르기, 비염, 천식, 아토피 등 건강 특이사항은 민감정보에 해당할 수 있어 일반 개인정보 처리와 분리하여 동의를 받습니다. 입력하지 않아도 기본 리포트를 이용할 수 있지만 개인화 범위는 줄어들 수 있습니다. 동의한 건강 정보는 맞춤 리포트 제공에만 이용하며, 프로필 삭제·회원 탈퇴 또는 동의 철회 시까지 보관한 뒤 지체 없이 파기합니다.
>
> 아동의 정보를 입력하는 사람은 해당 아동의 법정대리인이어야 합니다. 법정대리인은 처리 내역 열람·정정·삭제·동의 철회를 요청할 수 있으며, 운영자는 필요할 경우 이메일 등으로 동의 주체와 관계를 추가 확인할 수 있습니다.

### 3.4 개인정보처리방침 §3 「베타테스트 분석 및 자유 의견」 (`beta_analytics` 상세) — [app/privacy/page.tsx](../app/privacy/page.tsx)

> 베타 사용 기록 분석은 가입 시 약관 동의에 포함해 안내하며, 동의 전에는 분석 이벤트를 전송하지 않습니다. 페이지 방문, 온보딩 단계, 가입 완료, 리포트 조회·새로고침·오류, 체크리스트 사용을 기록하며 광고 프로파일링에는 사용하지 않습니다. 리포트 평가(도움이 되었나요)와 자유 의견은 이용자가 직접 제출한 경우에만 수집합니다.
>
> 자유 의견에는 아이나 보호자의 이름, 질병명, 연락처 등 개인정보를 적지 마세요.

### 3.5 개인정보처리방침 §6 「개인정보의 국외 처리」 (`overseas_transfer` 고지) — [app/privacy/page.tsx](../app/privacy/page.tsx)

> 아래 처리는 계정 저장과 맞춤 리포트 제공 계약을 이행하기 위해 필요한 처리위탁·보관에 해당하며, 개인정보 보호법 제28조의8에 따라 이 방침에 공개합니다. 전송은 서비스 이용 시 암호화된 네트워크를 통해 이루어집니다. 해당 처리를 원하지 않으면 서비스 이용을 중단하고 삭제를 요청할 수 있습니다.
>
> - **Supabase, Inc.** — 인증 및 데이터베이스 운영 · 계정, 아동 프로필, 동의·사용·의견 기록 · 국내 보유 기간과 동일
> - **Vercel Inc. (미국 등)** — 웹 호스팅·보안·장애 대응 · IP 주소, 접속 요청 및 기술 로그
> - **Anthropic, PBC (미국)** — AI 리포트 생성 · 아동 프로필·건강 특이사항·일정·환경정보와 리포트 요청 내용 · API 입출력 원칙적으로 최대 30일

> 이용약관·개인정보처리방침 전문은 코드가 단일 진실이며, 각각 [app/terms/page.tsx](../app/terms/page.tsx)·[app/privacy/page.tsx](../app/privacy/page.tsx)에서 확인한다.
