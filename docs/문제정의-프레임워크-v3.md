# 아이데이(AiDay) 문제정의 프레임워크 v3

> **기준 축 (절대 원칙):** 아이데이는 '외출 준비 도우미'가 아니다. 부모의 하루 육아 의사결정이 시작되는 **첫 판단** — 오늘의 환경정보를 내 아이 기준으로 해석해 옷차림·준비물·오늘 하루의 케어 방식을 결정하는 일 — 을 지원하는 서비스다. 이 포지셔닝은 모든 문서·피치·기능 설계에서 흔들리지 않는다.
>
> **v3에서 달라진 것:** v2가 '하루의 첫 육아 판단'을 근본 문제로 두었다면, v3는 이를 **상위 구조 문제(가족 운영 책임의 집중)의 대표 증상이자 현재 MVP의 진입점**으로 재배치한다. 제품 범위는 바뀌지 않는다 — 바뀐 것은 이 작은 시작점이 어떤 큰 문제에 연결되는지에 대한 설명이다. 전체 논증: [PROBLEM-THESIS.md](PROBLEM-THESIS.md)
>
> v2([문제정의-프레임워크-v2.md](문제정의-프레임워크-v2.md))는 당시 사고의 기록으로 보존한다. 페르소나 상세(서연의 Before/After 시나리오 전문)는 v2가 원본이다.

## 0. 문제의 구조: 상위 문제 → 증상 → 진입점

```
상위 구조적 문제
└─ 가족 운영의 기억·판단·예측·조율 책임이 한 사람에게 집중됨
   │  (만 1~8세 자녀를 둔 맞벌이 가정 — 실행은 나눠도 관리·판단 노동은 잘 나눠지지 않는다)
   │
   └─ 반복적으로 나타나는 대표 증상
      ├─ 아침 옷차림·케어 판단          ← 매일, 전 가정, 즉시 검증 가능
      ├─ 준비물·기관 공지 확인과 누락
      ├─ 일정 충돌과 변수 대응
      ├─ 아이 질병 시 돌봄 공백
      └─ 배우자·조부모·기관 간 조율

현재 MVP가 선택한 진입점 (웨지)
└─ 환경 궤적 × 아이 체질 × 오늘 일정을 결합한 '아침의 첫 육아 판단'
   → 신뢰 확보 후 인접 증상(공지·준비물·조율)으로 단계적 확장 (각 단계 행동 검증 통과 조건)
```

행동 근거 ([맘테스트 n=36](validation/2026-07-문제검증-맘테스트.md), 2026-07):

- 담당 집중: 평일 아침 준비를 **주 5일 전담 47.2% vs 0일 19.4%** — 전담·비담당으로 나뉘는 분포로, 운영 책임이 특정 보호자에게 집중될 가능성을 시사 (응답자 간 분포이며 가구 내 짝 조사 아님. 아빠 52.8% 표본 — 성별 문제가 아니라 담당자 구조 문제)
- 증상의 실재: 아침 환경 확인 주 3일+ **75.0%**, 최근 한 달 내 실패·재작업 사건 **52.8%**, 워크어라운드 실행 중 **83.3%**

## 1. 고객의 입장에서 생각한다: 디자인 싱킹

**질문: 고객(만 1~8세 자녀를 둔 맞벌이 부모)은 어느 순간, 어디서 가장 불편해하는가?**

매일 아침, 하루가 시작되는 순간이다. 부모의 하루 육아는 "오늘은 어떤 날인가, 그래서 내 아이에게 뭐가 필요한가"라는 판단에서 시작된다. 문제는 이 첫 판단이 출근·등원 준비가 겹치는 가장 바쁜 시간대에, 매일, 처음부터 다시 수행된다는 것이다.

더 깊은 문제는 **이 판단이 불완전한 입력값으로 이루어질 수밖에 없는 구조**라는 점이다. 판단에 필요한 입력은 '오늘 하루의 시간대별 환경 궤적 × 아이의 일정 × 아이의 체질'인데, 바쁜 아침에 이 결합을 수행할 인지 여력이 없다 (v2 8번 페르소나 — 서연은 아무것도 게을리하지 않았지만 실패했다).

맘테스트가 이 구조를 행동으로 확인했다: 판단 시 참고 대상이 날씨 앱(63.9%)·당일 컨디션(41.7%)·창밖 체감(38.9%)·기관 공지(27.8%)·경험과 감(27.8%)으로 **파편화**되어 있고, "확신은 없었지만 시간이 없어 일단 결정"(13.9%), "준비가 적절했는지 등원 후에도 신경 쓰임"(22.2%)이라는 인지 부담의 흔적이 함께 나타난다.

그리고 이 불편의 최종 형태는 개인의 피로가 아니라 **가족 운영의 취약성**이다: 판단 맥락이 담당자 한 명의 머릿속에만 있으므로, 그 사람이 아프거나 부재하면 가족의 아침이 흔들린다.

## 2. 이 문제가 고객의 무엇을 해결하려고 하나: JTBD

- **기능적 Job:** "오늘 하루 내 아이를 어떻게 케어할지, 하루의 첫 판단을 빠르고 정확하게 끝내고 싶다." 정보 확인이 아니라 **판단의 완료**가 Job이다. '정확함'의 기준은 지금 이 순간이 아니라 오늘 하루 전체다.
- **감정적 Job:** "내가 뭘 놓쳐서 아이가 고생하는 일이 없기를." 잘못된 판단에 대한 불안과 실패 후 죄책감의 해소.
- **사회적 Job:** "바쁘지만 아이를 세심하게 챙기는 부모이고 싶다."
- **(v3 추가) 운영적 Job:** "이 모든 것을 나 혼자 기억하고 있지 않아도 되면 좋겠다." — 판단 맥락을 개인의 머릿속에서 시스템으로 옮기는 것. 맘테스트의 워크어라운드(전날 확인 41.7%, 여벌옷 상비 33.3%, 역할 분담 25.0%)는 부모들이 이 Job을 이미 수동으로 수행 중임을 보여준다.

핵심 통찰: 부모가 고용하는 것은 '날씨 해석기'가 아니라 **'하루 육아의 첫 판단을 함께 내려주는 파트너'**다. 이 Job은 외출 여부와 무관하게 매일 발생한다.

## 3. 문제를 해체한다: 제1원리 사고

'원래 그래왔으니까' 남아있는 가정들:

- **"환경 정보의 해석은 부모가 한다"** → 해석·판단의 주체가 사람이어야 할 이유는 없다. AI가 아이 컨텍스트를 알면 판단까지 제공 가능하다.
- **"옷차림 판단의 기준은 현재 날씨다"** → 판단의 정답은 하루의 시간대별 환경 궤적과 아이 일정의 교차점에 있다.
- **"육아 앱 = 기록 도구"** → 신생아기의 관성. 유아기 이후의 매일의 Job은 기록이 아니라 판단이다.
- **"매일의 판단은 매일 새로 해야 한다"** → 입력값은 매일 바뀌지만 판단의 틀(아이 특성·과거 반응)은 누적 가능하다 → Family Memory의 존재 이유 (장기 가설).
- **(v3 추가) "집안일을 나누면 육아 부담도 나눠진다"** → 실행 노동(옷 입히기·등원시키기)과 **관리·판단 노동(무엇이 필요한지 알아내고 결정하고 위임하는 일)**은 다른 층위다. 실행은 나눠도 관리가 한 사람에게 남으면 운영 책임은 집중된 채다. 생활시간조사(2024)에서 맞벌이 가사노동 분담은 개선 추세(남편 +13분/아내 −17분)지만, 이 조사가 측정하는 것은 실행 시간이지 관리·판단 노동이 아니다.
- **"아침은 원래 정신없는 것"** → 첫 판단이 대행되면 부모에게는 확인과 실행만 남는다.

## 4. 문제의 원인을 끝까지 추적한다: 5 Why

**출발 현상:** 하루의 첫 육아 판단이 가장 바쁜 시간대에 매일 처음부터 다시 수행되며 지속적인 인지 부담이 되고, 입력값이 축소된 판단은 케어 공백으로 이어진다.

1. **왜 매일 부담인가?** → 가장 바쁜 시간대에 여러 변수를 종합해야 해서, 접근하기 쉬운 입력값(현재 날씨) 하나로 판단이 축소된다.
2. **왜 미리 해둘 수 없나?** → 입력값(기온·일교차·미세먼지·컨디션)이 당일 변수라 어제의 결론을 재사용할 수 없다.
3. **왜 인지 자원이 많이 드나?** → 입력이 4개 축(환경 궤적/체질·건강/오늘 일정/케어 옵션)에 걸쳐 있고 여러 소스에 파편화되어, 결합이 부모의 머릿속에서 이루어진다.
4. **왜 부모가 직접 결합해야 하나?** → 어떤 서비스도 '내 아이'를 모르기 때문에. 정보 앱은 일반 데이터만 제공하고, 생성형 AI는 매번 재설명이 필요하다.
5. **왜 어떤 서비스도 내 아이를 모르나?** → 아이의 특성·이력·반응을 저장하고 환경 데이터와 결합해 추론하는 구조가 시장에 없어서.

**→ 직접 원인: 매일 새로 발생하는 '하루의 첫 육아 판단'을 내 아이 기준으로 수행해 줄 구조의 부재.**

**(v3 추가) 6. 왜 이 부재가 '한 사람'의 부담이 되나?** → 판단에 필요한 맥락(체질·일정·과거 반응·기관 요구)이 특정 보호자 한 명의 머릿속에만 축적되기 때문에. 맥락을 가진 사람이 판단 담당자가 되고, 담당은 자기강화된다(맥락이 쌓일수록 그 사람이 더 잘 판단하므로 더 맡게 된다).

**→ 근본 구조: 가족 운영의 판단 맥락이 시스템이 아니라 개인에게 저장되는 구조.** 솔루션 사슬은 v2와 동일하게 역순으로 끊되, 종착점이 하나 늘어난다 — 판단 맥락을 개인의 머릿속에서 가족이 공유하는 시스템으로 이전하는 것 (장기).

## 5. 업무 프로세스를 재정의: 시스템적 사고

**기존 프로세스:** 기상 → 현재 기온 확인 → (머릿속) 판단 → 실행 → 실패 시 죄책감 → 매일 리셋. 판단 단계 전부가 담당 부모 몫이다.

**재설계 프로세스 (아이데이):** (기상 전) AI가 시간대별 환경 예보 × 아이 프로필 × 일정으로 판단 완료 → 아침 브리핑 선제 제공 → 부모는 **확인 + 예외 수정만** → 수용/거부·결과 피드백이 누적 → 판단이 점점 정확해짐.

구조적 전환 세 가지:

1. "부모가 묻고 AI가 답한다" → **"AI가 먼저 제안하고 부모가 승인한다"**
2. 매일 리셋되는 판단 → **매일의 판단이 자산으로 누적** (Family Memory — 장기 가설)
3. (v3 추가) 판단 맥락의 저장소가 **담당자 개인의 머릿속 → 가족이 공유하는 시스템** — 누가 아침을 담당하든 같은 품질의 판단이 가능해지는 것. 공동 양육자 동기화(Post-MVP)가 기능 추가가 아니라 구조 전환인 이유.

## 6. 마지막 점검: 문제해결의 증명

측정 대상은 "외출 준비가 편해졌나"가 아니라 **"하루의 첫 육아 판단이 아이데이로 대체되었나"**이다. KPI 체계는 v2·[PRD §11](../PRD.md)을 유지한다:

| 지표 | 검증하는 것 |
|---|---|
| **아침 재방문율 ≥30%** (북극성) | '매일의 첫 판단'이라는 Job 정의의 실증 |
| 판단 대체율 (브리핑 확인 후 추가 탐색 없이 종료) | 판단 대행의 실작동 |
| 외출 없는 날 리텐션 | "외출 앱이 아니라 데일리 케어 판단 앱" 포지셔닝의 데이터 증명 |
| 추천 수용률·수용률 기울기 | 개인화 체감 — "쓸수록 정확해진다" 주장의 실증 |
| (v3 추가 후보) 워크어라운드 감소 | 브리핑 도입 후 전날 확인·여러 앱 비교 등 수동 해결책이 줄었는가 — 맘테스트 Q10을 베이스라인으로 활용 |
| (v3 추가 후보) 타 보호자 실행 가능성 | 주 담당자의 설명 없이 다른 보호자가 브리핑만으로 실행할 수 있는가 — 컨시어지 테스트 정성 관찰. '판단 맥락의 시스템 이전'(상위 문제) 가설의 행동 신호 |

**문제의 실재와 사업성 검증의 구분:** 문제의 실재(반복 행동·사건·워크어라운드)는 확인됐다. 사업성(반복 사용·지불)은 베타 행동 지표와 별도 실험이 담당한다. 이 구분을 흐리지 않는다 — 전체 검증 상태는 [PROBLEM-THESIS §9](PROBLEM-THESIS.md#9-아직-검증되지-않은-가설-정직성-표) 참조.

**v3 관점의 재해석:** 서연의 하루에서 아이데이가 현재 대체하는 것은 '아침의 첫 판단' 하나다. 그러나 서연이 지고 있는 것은 그 판단 하나가 아니라 — 공지 확인, 준비물 기억, 병원 일정, 배우자에게 부탁할 일의 정의까지 — **가족 운영의 관리 노동 전체**다. 아침 판단은 그 전체 부담에 매일 접촉하는 첫 지점이기 때문에 웨지로 선택되었다.

## 8. AI를 위한 프롬프트 생성

PRD 생성 프롬프트 골격은 v2 §7을 유지한다. v3에서 추가되는 컨텍스트 한 줄:

> **[상위 문제]** 이 기능이 해결하는 것은 '가족 운영의 기억·판단·조율 책임이 한 사람에게 집중된 구조'의 대표 증상인 '아침의 첫 육아 판단'이다. 기능 범위는 아침 판단으로 한정하되, 출력 설계는 담당자가 아닌 다른 보호자가 읽어도 즉시 실행 가능한 수준의 완결성을 갖춰야 한다 (판단 맥락의 시스템 이전이라는 장기 방향과 정합).
