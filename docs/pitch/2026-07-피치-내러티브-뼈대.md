# AiDay 피치 내러티브 뼈대 (2026-07)

> **목적:** 1주 내 피치·베타를 위한 슬라이드별 골격. 채점 기준 2개를 정면으로 충족한다.
> **채점 기준 ①** '어떻게 돈을 벌 것인가'가 나와야 함 → 슬라이드 8이 전담.
> **채점 기준 ②** 기능 나열이 아니라 유저 시나리오(유저 flow)대로 설명 → 덱 전체가 **서연의 하루**를 따라 흐른다. 기능 표는 어디에도 넣지 않는다.
>
> 원천: [서연 페르소나](../문제정의-프레임워크-v2.md#8-대표-유저-페르소나-서연-상세) · [상위 문제 논증](../PROBLEM-THESIS.md) · [맘테스트 n=36](../validation/2026-07-문제검증-맘테스트.md) · [가설검증 n=17](../validation/2026-05-사전-가설검증-설문.md)

## 관통 원칙 (덱 전체에 적용)

1. **주인공은 제품이 아니라 서연이다.** 매 슬라이드가 "서연이 지금 무엇을 겪는가"로 열린다. 제품은 서연의 흐름 속에서 자연스럽게 등장한다.
2. **기능을 나열하지 않는다.** "환경 API 4종·옷차림 추천·건강팁" 같은 표 금지. 대신 "07:10, 판단이 이미 끝난 채 도착한다"처럼 **장면**으로 보여준다.
3. **정직하게 단계를 구분한다.** 검증된 것(문제 실재)과 미검증(지불의사·반복사용)을 섞지 않는다 — 심사역이 가장 신뢰하는 지점.
4. **10~11장.** 한 슬라이드 = 한 메시지.

---

## 슬라이드별 골격

### 0. 타이틀
- **핵심 메시지(사용자 언어):** "매일 아침, 오늘 우리 아이에게 뭐가 필요한지 먼저 정리해 주는 AI"
- **담을 것:** 서비스명·한 줄 훅·발표자. 로고. 군더더기 없이.
- **채점 연결:** ② 유저 언어로 시작 (내부 전략어 '운영 에이전트'는 여기 쓰지 않는다).

### 1. 문제 장면 — 서연의 무너진 아침 (flow 시작)
- **핵심 메시지:** "서연은 아무것도 게을리하지 않았다. 그런데 지우는 감기에 걸렸다."
- **담을 것:** Before 시나리오 압축 — 07:00 현재 기온 20°만 보고 합리적으로 판단 → 11시 산책 28°에 땀 → 17시 하원 17°에 추위 → 저녁 감기 + 죄책감. 타임라인 한 줄로.
- **왜 이 슬라이드:** 실패 원인이 '노력 부족'이 아니라 '판단 구조의 결함'임을 감정으로 각인. 심사역이 서연에게 이입하게 만드는 것이 목표.
- **채점 연결:** ② 문제를 데이터가 아니라 사람의 하루로 연다.

### 2. 이건 서연 혼자의 일이 아니다 — 문제의 크기
- **핵심 메시지:** "작은 판단이 매일, 한 사람에게 쌓인다."
- **담을 것:**
  - 상위 문제 한 줄: 맞벌이 가정에서 아이 하루를 굴러가게 하는 기억·판단·조율 책임이 한 보호자에게 집중된다.
  - **행동 데이터(자체 맘테스트 n=36):** 주 3일 이상 아침 환경 확인 **75%** · 최근 한 달 실패·재작업 사건 **52.8%** · 이미 자기만의 해결책(전날 확인·여벌옷 상비) 실행 중 **83%**.
  - 시장 배경 한 줄: 막내 6세 이하 맞벌이 가구 53.2% (성평등가족부 2025).
- **왜 이 슬라이드:** "이게 큰 문제냐"는 반론을 사업 언어(빈도·행동·워크어라운드)로 선제 차단.
- **채점 연결:** 문제 실재성을 의향이 아니라 **행동**으로 — 심사 신뢰도.

### 3. 왜 아직 아무도 못 풀었나 — 화이트스페이스
- **핵심 메시지:** "기존 서비스는 정보를 주지만, 판단을 완료해 주지 않는다."
- **담을 것:** 4개 대안이 비어 있는 지점 한 장 — 날씨앱(수치만)·기록앱(유아기엔 판단이 Job)·맘카페(내 아이 아님)·범용 AI(매번 재설명). 직접 경쟁자 부재 = 화이트스페이스.
- **주의:** 이건 기능 비교표가 아니라 "왜 서연의 문제가 남아있는가"의 설명. 한 줄씩.

### 4~6. 솔루션 = 서연의 달라진 하루 (제품을 flow로 시연 · 데모 3화면과 1:1)

> 이 3장이 **베타 UI에서 반드시 다듬어야 하는 화면**과 정확히 일치한다. 여기만 데모 품질로 올린다.

**4. 한 번만 알려주면 (온보딩)**
- 메시지: "지우가 어떤 아이인지 한 번만 알려주세요."
- 장면: 온보딩 5단계 — 이름·나이·체질(땀 많음)·일정(등원/산책/하원). 스크린샷 1장.
- flow 강조: 이 입력이 매일 반복되는 게 아니라 **한 번 쌓이면 계속 쓰인다**(Family Memory 원료).

**5. 07:10, 판단이 이미 끝난 채 도착한다 (핵심 화면)**
- 메시지: "서연은 이제 판단하지 않는다. 확인만 한다."
- 장면: 아침 브리핑 카드 스크린샷 — 훅("일교차 11° — 겹쳐 입기 필수") + 지우 이름·체질 반영 + 실행 체크리스트(반팔+겉옷 / 여벌옷 / 알림장 문구).
- **이 슬라이드가 덱의 심장.** 가장 공들인 스크린샷이 여기 들어간다.

**6. 실행하고, 쓸수록 정확해진다**
- 메시지: "체크하고 나가면 끝. 저녁에 결과 한 번, 내일은 더 정확해진다."
- 장면: 체크리스트 실행 + 저녁 결과 피드백(더움/적당/추움) → 다음 판단에 반영되는 루프.
- flow 강조: 여기서 **해자의 씨앗**(수용/거부·결과 이력 누적)을 자연스럽게 노출.

### 7. 왜 우리가 이기나 — 해자는 아이디어가 아니라 실행
- **핵심 메시지:** "따라 하기 쉬운 건 아이디어고, 어려운 건 실행이다."
- **담을 것:** 3중 실행 해자 — ① 선제 푸시(묻기 전에 먼저) ② 체질 개인화(내 아이 기준) ③ 신뢰(의학 근거·안전 레이어). 참조 모델(Oura·열나요 등)은 있으나 이 조합의 직접 경쟁자는 없음.
- **채점 연결:** "GPT로 되는 거 아니냐"에 대한 답 = 누적 맥락 + 선제성.

### 8. ⭐ 어떻게 돈을 버는가 (채점 필수 슬라이드)
- **핵심 메시지:** "무료로 매일 쓰게 만들고, 가족 운영을 대신 짊어질 때 과금한다."
- **담을 것 (3단):**
  1. **지금(무료):** 아침 브리핑 = 데일리 리텐션 엔진. 무료로 반복 사용을 검증하는 단계 — 아침 재방문율이 북극성.
  2. **유료 전환(B2C 구독):** 무료 웨지가 신뢰를 만들면, **Post-MVP 로드맵이 곧 유료 가치**가 된다 — 다자녀 관리 · Family Memory 개인화("쓸수록 정확") · 알림장·공지 통합 · 공동육아 동기화(다른 보호자도 실행). "판단 하나"가 아니라 "가족 운영을 대신 짊어지는 값".
  3. **Second engine(B2B2C):** 어린이집·기관 제휴(기관이 부모에게 제공), 보험·유아용품사 데이터 기반 제휴 — 단, MANIFESTO대로 **쇼핑앱이 아니라 판단이 먼저**.
- **시장:** 막내 6세 이하 맞벌이 가구 → TAM 한 줄(가구 수 × 예상 ARPU).
- **정직성 한 줄:** "지불의사는 아직 미검증 — 확산 단계에서 검증한다. 지금 증명하는 건 매일 여는가다." (심사역은 과장보다 이 정직함을 높게 본다.)
- **채점 연결:** ① 전담 충족. 단순 "구독 받겠다"가 아니라 **무료 웨지 → 운영 시스템 유료화**라는 논리로.

### 9. 우리는 이미 검증했고, 지금 다음을 검증 중이다
- **핵심 메시지:** "문제는 행동으로 증명됐다. 지금은 '매일 여는가'를 본다."
- **담을 것:** 검증 사다리 한 장 — 가설검증 인터뷰(n=17) → 문제검증 맘테스트(n=36, 행동) → **오픈 베타(지금)** → 컨시어지 테스트. 그리고 3대 행동 검증 질문: ① 기존 탐색을 멈췄는가 ② 준비 행동이 바뀌었는가 ③ 다른 보호자도 설명 없이 실행했는가.
- **채점 연결:** 로드맵이 아니라 **증거의 축적**으로 보이게.

### 10. 팀 · Ask · 다음 6주
- **담을 것:** 팀 한 줄, 지금 필요한 것(베타 유저·피드백·자원), 6주 안에 증명할 것(아침 재방문율).
