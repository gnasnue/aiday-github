## Step 0: Nuclear Scope Challenge

### 0A. Premise Challenge

**해결하려는 문제:** Next.js 15 App Router에서 Claude API SSE 스트리밍이 안정적으로 동작하지 않음. 스트리밍을 제거하고 단순 JSON 응답으로 교체.

**올바른 문제인가?** 부분적으로 그렇다. 스트리밍 제거는 호환성 문제를 해결하지만, UX 회귀를 초래한다. 이전에는 AI 리포트가 글자 단위로 나타났지만 (반응적 느낌), 이제는 ~1-2초 대기 후 한꺼번에 표시된다. Haiku 모델의 5-7문장 응답에서는 수용 가능한 수준이다.

**아무것도 안 하면?** `d379e61` 커밋의 스트리밍 코드가 현재 배포 환경에서 깨져 있거나 불안정하다. 방치 = 핵심 기능 고장.

### 0B. 기존 코드 활용

- `buildRecommendation()` (`lib/recommendation-engine.ts`) — Claude API 없이 규칙 기반 추천 생성. AI 리포트와 병렬로 존재.
- `mockWeather` (`lib/weather-mock.ts`) — 날씨 API 실패 시 fallback으로 사용됨.
- `loadProfiles()` (`lib/profile.ts`) — localStorage 프로필 저장소.

**DRY 위반:** `fetchEnv`와 `fetchReport` 두 useEffect 모두 거의 동일한 날씨/대기질 fetch 코드를 복사-붙여넣기로 사용 중.

### 주요 아키텍처 문제

1. **중복 API 호출 (Critical):** 페이지 로드마다 기상청·에어코리아 API를 4회 호출 (2회여야 함). `fetchEnv`에서 이미 가져온 데이터가 `weatherData` 상태에 있지만, `fetchReport`가 이를 무시하고 재호출.

2. **에러 미전파:** `client.messages.create()` 실패 시 Next.js가 500 오류로 잡음 → 프론트엔드는 `!res.ok` → `setAiLoading(false)` 호출 → 사용자에게 아무 안내 없음.

3. **암묵적 의존성 체인:** `fetchEnv`가 `aiLoading=true`를 설정 → 두 번째 useEffect가 이를 감지해 실행. 이 implicit trigger는 취약하고 가독성이 낮음.

`git revert` — 두 파일 변경으로 DB 마이그레이션 없음. 즉시 안전하게 롤백 가능.

## Section 5: 코드 품질 리뷰

### DRY 위반 (중요)

날씨/대기질 fetch 코드가 두 useEffect에 거의 동일하게 복사됨:

```typescript
// fetchEnv (line ~104)
const [weatherRes, airRes] = await Promise.allSettled([
  fetch("/api/weather?lat=37.5665&lon=126.9780").then((r) => r.json()),
  fetch("/api/air?station=%EC%A2%85%EB%A1%9C%EA%B5%AC").then((r) => r.json()),
]);

// fetchReport (line ~130) — 거의 동일
const [weatherRes, airRes] = await Promise.allSettled([
  fetch("/api/weather?lat=37.5665&lon=126.9780").then((r) => r.json()),
  fetch("/api/air?station=%EC%A2%85%EB%A1%9C%EA%B5%AC").then((r) => r.json()),
]);
```

**수정 방법:** `fetchEnvironmentData(): Promise<{ weather, air }>` 헬퍼 추출 후 한 번만 호출.

### `renderRich()` 데드 코드

시스템 프롬프트가 `마크다운 없이 순수 텍스트로` 지시하지만, `renderRich()`는 `**bold**`와 `__bold__` 파싱을 수행. 모델이 지시를 따르면 이 함수는 데드 코드. 유지하려면 검증 추가, 제거하려면 삭제.

### `message.content[0]` 경계 검사 누락

```typescript
// 현재 (위험)
const text = message.content[0].type === "text" ? message.content[0].text : "";

// 수정 후
const text = message.content[0]?.type === "text" ? message.content[0].text : "";
```

### 암묵적 useEffect 체인

`aiLoading` 상태를 신호로 사용하는 두 번째 useEffect 패턴 (`fetchEnv` → `aiLoading=true` → `fetchReport` 트리거)은 fragile하고 가독성 낮음. `fetchEnv` 내에서 데이터 fetch 후 직접 `fetchReport(weather, air)` 호출 권장.

## Section 7: 성능 리뷰

| 항목 | 현황 | 영향 | 우선순위 |
|---|---|---|---|
| 중복 API 호출 | 기상청/에어코리아 4회 호출 (2회여야 함) | High | P1 |
| Claude Haiku 지연 (~1-1.5s p50) | Non-streaming으로 전체 대기 | Med | P2 (수용 가능) |
| AI 리포트 캐싱 없음 | 매 페이지 로드마다 Claude 호출 | Med | P2 |
| `loadProfiles()` 동기 호출 | useState 초기화에서 localStorage 동기 읽기 | Low | P3 |

**중복 API 호출 상세:**
정부 공공 API(기상청, 에어코리아)는 속도 제한과 지연이 있음. 페이지 로드마다 4번 호출하면 2배 비용과 지연. `fetchEnv`에서 가져온 데이터를 `fetchReport`에 전달하면 즉시 해결.

**5분 캐시 기회:** 같은 날씨 데이터로 Claude를 여러 번 호출하지 않도록 localStorage에 5분 TTL 캐시를 추가하면 아침에 앱을 반복적으로 확인하는 사용자의 API 호출을 대부분 제거 가능.

## Section 11: 디자인 & UX 리뷰

### 인터랙션 상태 커버리지

| 기능 | 로딩 | 빈 상태 | 에러 | 성공 | 프로필 전환 |
|---|---|---|---|---|---|
| AI 리포트 | ✅ (aiLoading=true) | ✅ (aiMessage="") | ❌ 조용한 실패 | ✅ (data.text 표시) | ❌ stale 리포트 |

### 주요 UX 문제

1. **조용한 에러 상태:** `!res.ok` 시 로딩 스켈레톤이 사라지고 아무것도 표시되지 않음. 다음과 같은 fallback 필요:
   > "오늘 리포트를 불러오지 못했어요. 잠시 후 다시 시도해주세요."

2. **프로필 전환 시 stale 리포트:** 다른 아이 프로필로 전환해도 새 AI 리포트가 생성되지 않음. 부모가 잘못된 아이의 리포트를 보게 됨.

### 사용자 흐름 다이어그램

```
페이지 로드
    │
    ├─► 날씨 카드 [로딩]
    │       └─► [데이터] or [mockWeather fallback]
    │
    ├─► AI 리포트 섹션 [로딩 스켈레톤]
    │       ├─► [성공] 리포트 텍스트 표시
    │       └─► [실패] ← 현재: 스켈레톤 사라짐, 공백
    │                  ← 목표: "리포트를 불러오지 못했어요" fallback
    │
    └─► 프로필 전환
            ├─► 날씨 카드 [갱신 없음 — 날씨는 공통]
            └─► AI 리포트 ← 현재: 이전 아이 리포트 유지
                          ← 목표: 새 아이 리포트 재생성
```
