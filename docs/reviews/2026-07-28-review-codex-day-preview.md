## 치명적 문제

### P1-1. 실행 순서와 시각 강조의 역전
아침에 부모가 물리적으로 하는 순서는 **① 여벌 상의를 가방에 넣기 → ② 전달하기**다. 그런데 화면은 ②를 Hero의 유일한 primary solid CTA로, ①은 아래 카드의 저강조 토글 행으로 둔다. 가방에 안 넣은 채 전달 문구만 복사하면 그날의 실패는 그대로다. Hero CTA를 "여벌 상의 챙기기 → 전달 문구 복사" 2스텝으로 묶거나, Hero에 ①을 흡수해야 한다.

### P1-2. 안전·정직성 고지가 가장 안 보이는 색으로 쓰였다
`text-faint`(3.02:1, **현행 DESIGN.md가 의미 텍스트에 금지**)로 렌더되는 문장들이 하필 전부 고지다 — "오늘 결과는 체질 진단이 아니며…", "실제 전송·저장은 하지 않아요", "한 번의 결과로 체질이나 경향을 확정하지 않아요". 정직성을 지키려고 쓴 문장이 AA 미달 색이라 실제로는 안 읽힌다. `muted-foreground` 이상으로 올려야 한다.
같은 계열: `NEW` 배지가 `bg-primary` + 흰색 **11px bold**(≈2.9:1) — DESIGN.md는 primary-foreground 흰색을 17px bold 이상에서만 허용한다.

### P1-3. "실행하지 못했어요" 선택 시 자기모순
`not_executed`를 고르면 recap은 "이 결과는 경향으로 계산하지 않을게요"인데, 상태는 `result_added`로 전이하고 Hero는 **"오늘 결과가 다음 판단에 연결됐어요 / 다음엔 다시 설명하지 않아도 돼요"**를 띄운다. 계산에서 빼겠다고 해놓고 연결됐다고 말한다. 미실행은 별도 상태(또는 Hero 문구 분기)로 갈라야 한다.

### P1-4. 베이스가 29커밋 뒤처져 디자인 계약이 어긋난다
`codex-work`는 `94a13f4` 기준이라 **2026-07-26 히어로 결정 이후**가 없다. 실제 결과: Hero가 `rounded-2xl`(20px) + 26px 헤드라인 — 현행 계약은 `rounded-3xl`(24px) + display **28/-0.028em**. 지금 main에 포팅하면 홈 히어로와 기하·타이포가 갈린다. Codex의 자체 디자인 리뷰가 "타이포 display 26 준수"라고 적은 것은 **구버전 DESIGN.md 기준**이라 현행에서는 틀린 판정이다.

### P1-5. `/preview/day`가 프로덕션에 그대로 나간다
`app/` 하위 정적 라우트라 배포 시 누구나 접근 가능하고, 내부에 허구 데이터(가짜 날짜·아이 이름)와 미구현 약속 문구가 있다. dev 게이트나 최소 `noindex`가 필요하다. *(공평하게: 내 워크트리의 `app/preview/hero-card`도 동일 문제다.)*

### P2 (모아서)
- **날짜 오류**: "10월 16일 **목요일**" → 2026-10-16은 **금요일**. 데모 중 누가 확인하면 신뢰가 깎인다.
- **aria-live 무력화**: Hero가 `key={state}`로 리마운트되는데 `aria-live="polite"`가 그 안에 있다. 라이브 리전은 콘텐츠 변경 **전에 DOM에 존재**해야 알림이 나가므로, 상태 전환이 스크린리더에 안 읽힐 가능성이 높다. 리전을 바깥 고정 요소로 빼야 한다.
- **"완료" 라벨 모호**: 준비물 토글의 미완료 상태 우측 라벨이 "완료"(행동?) → 완료 시 "챙겼어요"(상태). 둘 다 상태 어휘로 통일해야 한다.
- **preview 날짜 vs 실제**: 시나리오가 10월인데 데모는 7월에 한다. 환절기 케이스라 의도는 이해되나, 발표에서 "지금 7월인데요?"가 나오면 설명 비용이 든다.

## 조정 합의 (3라운드, 2026-07-28) — 최종 판정 **HOLD SCOPE**

Codex의 2·3차 회신을 반영한 최종 합의. **루프(`예측 → 준비 → 전달 → 결과 회수 → 다음 판단 반영`)는 진행하되, 별도 `하루` 탭의 필요성은 미확정으로 둔다.**

### 합의된 제품 계약

1. **단일 당일 케어 계획 계약** (Codex 안 채택 — 내 "홈=판단/하루=실행" 문구 규칙보다 강함).
   문구 규칙은 구현이 어기면 조용히 갈라지지만, 공유 산출물은 구조적으로 갈라질 수 없다(홈↔env 모순 사고와 같은 계열의 재발 방지).
   ```
   당일 케어 계획: 무엇 · 언제 · 누가 · 왜 · 근거 반영(실제 사용된 과거 결과만)
   홈 = 결론과 즉시 실행 / 하루 = 실행 상태·전달·결과 회수 (같은 계획의 다른 깊이)
   ```
2. **엔진을 요구사항으로 고정하지 않는다** — 요구사항은 *단일 산출물 · 재현 가능한 우선순위 · 입력 출처 추적*. 안전·우선순위는 결정적 규칙, 표현은 AI(하이브리드).
   집행 규칙: **계획 객체가 과거 결과의 evidence 참조를 들고 있을 때만** "지난번 결과 반영" 문장을 렌더한다.
3. **시제 규칙** — 미래형 약속은 다음 판단이 생성되는 시점(다음 아침)에만. 현재형 설명은 과거 결과가 실제 입력에 들어간 경우에만.
4. **메타 라벨 제거, 실행문 우선** — "놓치면 안 될 한 가지"·"놓치기 쉬운 것" 모두 부모의 실수에 초점을 두므로 폐기. 라벨 없이 실행문("11시 산책 뒤, 여벌 상의로 갈아입혀 달라고 전달하세요") 또는 중립 라벨("오늘의 실행"·"오늘 미리 맞춰둘 케어").
5. **순위 계약 없으면 순위 주장 금지** — "가장 중요한·한 가지·1순위" 사용 금지(리포트 v27 "시점 단정 금지"와 같은 원칙).
6. **전달 대상** — 어린이집 재원 정보 확인 시 "어린이집에 전달", 그 외/미상은 "돌봄자에게 전달". **대상 선택 온보딩은 추가하지 않는다**(반복 사용 확인 후).
7. **지불 검증에 프로덕션 이식은 필수조건이 아니다** — 필요한 것은 "반복되고 중단 가능한 서비스 경험". 실데이터 작동 프로토타입 또는 7일 수동 컨시어지로 시작 가능. 판정은 4단계로 분리: 사용성(공유했는가) → 효용(수고가 줄었는가) → 의존(3일 박탈 시 재발) → 지불(실제 가격 앞 구매).

### 내가 추가한 보완 3건

- **(a) 탭 존속 질문은 알림 질문의 하위 문제다.** 결과 회수는 21시 Job, 브리핑은 07시 Job — 다른 세션이다. 그런데 탭이든 상세 화면이든 **저녁 진입 문제는 동일**하고, 진입을 만드는 것은 선제 알림(전날 저녁 알림 수요 64.7%)이다. 따라서 "하루 탭이 필요한가"는 알림 없이는 답이 나오지 않는다 → 컨시어지에 **저녁 수동 발송을 포함**시켜 이 질문을 함께 답한다.
- **(b) "홈에서 다 끝낸다"는 무비용 대안이 아니다.** 현재 홈은 프로필 → 히어로(판단+체크리스트+피드백) → 시간대별 환경 → 케어 플랜 → 건강 팁 → 오늘의 마무리 → 패스 배너로 이미 길다(히어로 단독 690px대). 전달까지 흡수하려면 **홈 IA 감사(무엇을 뺄지)가 선행**돼야 하며, 그 비용이 하루 화면 유지 비용보다 작다는 근거는 없다.
- **(c) HOLD SCOPE는 코드 롤백이 아니라 주장 수준에서 수용한다.** 하루 탭은 이미 구현·커밋됐고(건강팁 탭 자리 이관 포함) 되돌리는 비용이 얻는 것보다 크다. 따라서 **코드는 현행 유지 / 문서·발표는 "IA 미확정, 컨시어지 후 재판정"으로 표기 / 실제 확정은 7일 컨시어지 + 3일 박탈 이후**.
