# AiDay 현재 단계 엔지니어링 리뷰

## 사전 감사

- `npm.cmd run lint`: 통과
- `npm.cmd run build`: 통과
- 공개 배포 URL: HTTP 200 응답
- 테스트 스위트는 없다. 다음 변경부터는 최소한 API 경계와 핵심 판단 규칙에 대한 자동 테스트를 추가한다.

## 발견 사항

### T1 — P0: 공개 AI 리포트 API에 서버 측 호출 제한이 없다

`app/api/report/route.ts`는 인증·IP 제한·요청 크기 제한 없이 Anthropic API를 호출한다. 게스트 사용을 허용하는 제품 결정과 충돌하지는 않지만, 문서에 적힌 “IP당 일일 제한”은 구현되어 있지 않다. 누구나 반복 호출해 비용을 발생시킬 수 있다.

**조치:** Vercel KV/Upstash 또는 Supabase 기반의 서버 측 제한을 도입한다. IP별 일일 한도, 프로필별 짧은 쿨다운, 429 응답과 사용자 안내를 포함한다. 이를 닫기 전 공개 모집을 시작하지 않는다.

### T2 — P1: 화면 표시 지역과 실제 환경 데이터의 조회 지역이 다르다

`app/(main)/home/page.tsx`는 서울시청 좌표와 종로구 측정소를 고정 호출하면서, 화면에는 강남구로 표시하고 위치 변경은 준비 중 토스트만 보여 준다. 브리핑의 근거가 되는 데이터가 잘못 표시되는 문제다.

**조치:** 첫 온보딩에 지역 선택 하나를 넣고, 표시명·기상 좌표·대기질 측정소를 단일 매핑 테이블에서 함께 관리한다. 자동 위치 권한은 후순위다.

### T3 — P1: 새벽 기상청 조회가 전날 발표 시각으로 넘어가지 않는다

`app/api/weather/route.ts`의 `getBaseDateTime`은 오전 2시 30분 전에도 당일 02:00 발표 데이터를 요청한다. 이 시각의 데이터는 아직 발표 전일 수 있어 빈 응답·대체 데이터 표시로 이어질 수 있다.

**조치:** 첫 사용 가능 발표 시각 전에는 날짜를 전날로 넘겨 23:00 데이터를 요청하도록 수정하고, 00:00~03:00 경계 테스트를 추가한다.

### T4 — P1: 민감한 아동 정보의 처리 고지와 동의 기록이 완성되어 있지 않다

생년, 건강 관련 상태, 일정이 Supabase와 AI 리포트 요청에 포함되지만, 랜딩의 약관·개인정보처리방침 링크는 `#`이고 별도 동의의 저장 근거도 없다.

**조치:** 실제 문서 페이지, 필수/선택 동의 분리, 동의 버전·시각 저장, 보관 기간·삭제 경로, AI 제공자에 보내는 필드와 국외 처리 여부의 고지를 배포 전에 마련한다. 법률 자문이 필요한 항목은 전문가 검토를 받는다.

### T5 — P1: 제품 의사결정을 위한 관측 도구가 없다

코드베이스에서 분석 이벤트 도구와 오류 추적 도구를 찾지 못했다. 지금은 “누가 어디서 이탈했고 브리핑을 다시 봤는지”를 알 수 없다.

**조치:** 먼저 최소 이벤트만 계측한다: `landing_cta`, `onboarding_completed`, `briefing_viewed`, `checklist_completed`, `report_failed`, `evening_feedback_submitted`. 개인정보 원문은 분석 이벤트로 보내지 않는다.

### T6 — P2: 입력 검증과 실패 처리를 강화해야 한다

`/api/report`는 `req.json()`과 요청 본문을 신뢰한다. 외부 호출 전에 Zod 스키마·길이 제한·범위 검증을 두고, 잘못된 JSON에는 400을 반환해야 한다. 환경 API의 HTTP 오류도 클라이언트에서 명확하게 구분해 안내한다.

### T7 — P2: 알림 설정 UI는 있으나 실제 전달 체계는 없다

프로필의 `notif` 값은 저장하지만 manifest, service worker, 푸시 구독·발송 처리가 없다. 현재는 알림 기능을 약속하거나 성공 지표로 쓰면 안 된다.

### T8 — P3: 도구 체인 정리

`next lint`는 Next.js 16에서 제거 예정이라는 경고가 있다. 이후 별도 ESLint CLI로 옮기고, 의존성 버전도 잠근다. 빌드 경고의 Browserslist 데이터도 정기 갱신한다.

## 결론

P0(T1)과 P1(T2~T5)을 해결하면 제한된 7일 테스트를 시작할 수 있다. PWA나 채널 확장은 그 뒤의 일이다.
