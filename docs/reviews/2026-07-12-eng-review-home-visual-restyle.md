# 홈 화면 비주얼 리스타일 엔지니어링 리뷰

## 사전 감사

- 대상: 홈 리포트 표현, 상태 토큰, 라인 아이콘, 추천 아이템 SVG
- 데이터 호출·AI 캐시 키·외부 API 파라미터는 이번 변경에서 바뀌지 않았다.
- `npm.cmd run build`는 타입 검사와 정적 페이지 생성을 포함해 성공했다. Browserslist 데이터가 13개월 경과했다는 경고만 있었다.

## 발견 사항

### T1 — P1: 시간대별 환경 카드가 실조회 결과 대신 목데이터를 계속 표시

`fetchEnv`가 `weatherData`를 갱신하지만, 시간대 카드 렌더링은 `mockWeather.timeline`을 직접 참조한다. 카드가 실측 데이터를 쓴다고 고지하면서 목데이터를 보여 주므로, `docs/PRODUCT-DECISIONS.md`의 공개 베타 차단 항목과도 일치한다.

Before:

```tsx
{loading ? <Skeletons /> : mockWeather.timeline.map((t) => <TimelineCard key={t.time} {...t} />)}
```

After:

```tsx
{loading ? <Skeletons /> : weatherData.timeline.map((t) => <TimelineCard key={t.time} {...t} />)}
```

해결 조건: `fetchEnv`가 생성하는 `WeatherData.timeline`의 형태·아이콘 값을 보장하고, 실패 시에만 `mockWeather`로 폴백한다. 이 수정 전에는 공개 베타로 배포할 수 없다.

### T2 — P2: 날씨 아이콘 매핑이 맑음 이외의 상태를 모두 구름+해로 축소

새 `weatherIcon`은 `☀`가 들어간 경우만 `sun`을 쓰며, 흐림·비·눈 등 모든 나머지 값을 `cloudsun`으로 렌더링한다. 기존 이모지가 전달하던 강수 의미가 사라진다.

Before:

```tsx
const weatherIcon = (emoji: string) => (
  <LineIcon name={emoji.includes("☀") ? "sun" : "cloudsun"} size={24} />
);
```

After:

```tsx
const weatherIconByCondition: Record<WeatherCondition, LineIconName> = {
  sunny: "sun",
  partlyCloudy: "cloudsun",
  cloudy: "cloud",
  rain: "cloudrain",
  snow: "cloudsnow",
};
```

해결 조건: 문자열 이모지가 아니라 API의 하늘·강수 코드로 표현 모델을 만들고, 필요한 아이콘을 모두 제공한다.

### T3 — P2: AI 체크리스트 아이콘을 비구조화된 문장 정규식으로 판별

AI 응답은 임의의 아이콘·문구를 반환한다. 현재는 단어 포함 여부로 아이콘을 선택하므로, 새 표현이나 다의어가 추가되면 부정확한 아이콘 또는 경고 색 체크 아이콘으로 폴백한다.

Before:

```tsx
if (/물병|물통|물/.test(s)) return <LineIcon name="bottle" />;
return <CircleCheck />;
```

After:

```ts
type ChecklistItem = { kind: "mask" | "outerwear" | "moisturizer" | "other"; text: string };
```

해결 조건: `/api/report`의 JSON 스키마와 캐시 키를 함께 버전업하고 `kind`를 기준으로 아이콘을 그린다. 이는 P2이므로 T1 이후에 처리한다.

## 결론

P0은 없다. T1(P1)은 공개 베타 전 필수 수정이며, T2·T3(P2)는 홈 리포트가 실제 데이터로 전환되기 전에 함께 정리하는 편이 안전하다.
