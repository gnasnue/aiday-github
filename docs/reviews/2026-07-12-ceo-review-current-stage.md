# AiDay 현재 단계 제품 리뷰

## 한 줄 결론

AiDay는 부모가 아이 프로필을 입력하고, 당일 환경 데이터를 바탕으로 행동 가이드를 확인하는 **작동하는 MVP 프로토타입**이다. 그러나 아직 그 가이드가 매일 유용하고 신뢰할 만한지, 또 부모가 다시 찾아오는지를 측정할 수 없으므로 공개 베타나 기능 확장 단계는 아니다.

## 사전 감사

- 로컬 `HEAD`와 GitHub `main`은 모두 `cee679c`(2026-07-12)로 일치한다.
- 배포 주소 `https://aiday-demo.vercel.app/`는 HTTP 200으로 응답했다.
- `npm.cmd run lint`, `npm.cmd run build`는 모두 통과했다.
- 작업 폴더에는 아직 커밋하지 않은 홈 화면·스타일·일러스트 변경이 있다. 이 변경은 이번 제품 판단과 별도로 검토·커밋한다.

## 범위 판단

### 지금 풀려는 문제는 맞다

환경 수치를 나열하는 대신, 아이의 민감도와 일정에 맞춰 “오늘 무엇을 할지”를 알려 주겠다는 문제 정의는 `MANIFESTO.md`와 일치한다. 핵심 루프도 이미 존재한다.

`아이 정보 입력 → 오늘 브리핑 확인 → 준비물/행동 결정`

### 지금 만들지 말아야 할 것

- 새 탭, 건강 콘텐츠 확대, OOTD 시각화 고도화
- 네이티브 앱·복잡한 푸시 기능·카카오 연동
- 여러 지역·여러 외부 데이터의 기능적 확장

이들은 “브리핑이 실제 행동을 바꾸는가”를 확인하기 전에는 비용만 늘린다.

## 출시 전 반드시 닫을 결정

1. **데이터 신뢰성:** 표시 지역과 실제 조회 지역을 일치시키고, 새벽에도 기상 데이터가 정상적으로 나와야 한다.
2. **안전·비용 보호:** 로그인하지 않은 사용자의 AI 리포트 호출을 서버에서 제한해야 한다.
3. **민감정보 처리:** 아이의 생년·건강 관련 입력을 수집·외부 AI 처리한다는 사실, 보관·삭제 방법을 실제 약관과 개인정보처리방침으로 제공해야 한다.
4. **측정:** 가입, 온보딩 완료, 브리핑 노출, 체크 완료, 저녁 피드백을 기록해야 다음 판단을 데이터로 할 수 있다.

## 권장 실행 순서

1. 기술 차단 항목(P0/P1)을 고친다.
2. 이벤트 계측과 한 장짜리 개인정보/약관 페이지를 넣는다.
3. 지인·모집 패널 8~15가구에게 7일간 수동으로 테스트를 진행한다. 알림은 먼저 사람이 보내도 된다.
4. 매일 “브리핑 확인 → 실제 실행 → 저녁 만족/수정 의견”을 기록한다.
5. 재사용과 행동 변화가 보일 때에만 PWA·자동 알림을 구현한다.

## Go / No-go 기준 제안

- **Go:** 참여 가구의 절반 이상이 7일 중 4일 이상 브리핑을 확인하고, 절반 이상이 준비물·외출·옷차림 중 하나를 실제로 바꿨다고 답한다. 위험하거나 명백히 틀린 안내는 0건이다.
- **Hold:** 확인은 하지만 행동 변화가 적다. 첫 화면의 결론·근거·체크리스트를 다듬어 다시 시험한다.
- **No-go / 재정의:** 부모가 결과를 신뢰하지 않거나 환경 데이터의 개인화가 의사결정에 기여하지 않는다. 알림이나 새 기능을 추가하지 말고 문제 정의부터 다시 인터뷰한다.
