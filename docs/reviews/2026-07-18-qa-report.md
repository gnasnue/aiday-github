## Findings

### P1

**F-1. 잡초류 꽃가루 미조회 — 8월부터 꽃가루 지표가 상시 "낮음"으로 오표시 예정**
- `app/api/pollen/route.ts:102` — `weed: null // V3에 잡초 오퍼레이션 없음`
- 기상청 꽃가루농도위험지수는 참나무·소나무 4~6월, **잡초류 8~10월** 제공. 현재 코드는 oak·pine만 조회하므로 7월인 지금은 두 값 모두 시즌 외(null) → `pollenLabel(null)`이 "낮음"을 반환해 우연히 계절과 맞아 보이지만, **2주 뒤 잡초 시즌이 시작되면 실제 위험이 높아도 홈의 꽃가루 지표(시간대 카드·특이사항·마스크 준비물·envSignature 급변 판정)가 전부 "낮음"으로 고정**된다. 알레르기 체질 해석이 핵심 가치인 서비스에서 예정된 오작동.
- 권장: 공공데이터포털 명세에서 잡초류 오퍼레이션(예: `getWeedsPollenRiskIdxV3`) 존재 확인 후 조회 추가. (프록시 차단으로 이번 세션에서는 엔드포인트 직접 검증 불가 — 서비스 자체는 잡초류 지수를 제공함을 기상청 문서로 확인)

### P2

**F-2. 날씨 API 실패 시 mock 값이 실측처럼 노출**
- `app/(main)/home/page.tsx:238` (`useState<WeatherData>(mockWeather)`), `:797-813` (mock 슬롯 폴백), `:920-930` (nowWeatherItems), `:1337-1339` (신뢰 라인)
- 기상청 API가 통째로 실패하면 AI 카드 헤더에만 "기본 추천"이 붙고, **현재날씨 15°·습도 42%·시간대 12~21°·꽃가루 높음 등 mock 값이 실측처럼 표시**되며 신뢰 라인은 여전히 "기상청·에어코리아 실측 데이터"를 주장한다. 실구동(키 미설정)으로 재현 확인 — 7월에 "현재날씨 15°, 쌀쌀한 날씨" 리포트가 노출됐다.
- 권장: mock 폴백 시 현재 환경 한 줄·시간대 카드에 "예시 데이터" 표기(또는 미표시) + 신뢰 라인 문구 전환.

**F-3. 자외선·꽃가루 결측 시 "낮음" 표시 — 거짓 안심 (미세먼지 원칙과 비일관)**
- `lib/timeline.ts:75-80` — `pollenLabel(null)` → "낮음", `uvLevel(null)` → "낮음". 반면 `dustLabel(null)`은 "데이터 없을 때 거짓 안심을 주지 않는다"며 의도적으로 "보통"(71-72행 주석).
- `/api/uv`가 실패한 여름 한낮에 전 슬롯 "자외선 낮음"이 표시돼 선크림 신호가 사라진다. 같은 결측인데 지표별 철학이 다르다.
- 권장: uv·pollen도 결측 시 중립 표기("—" 또는 "보통")로 통일하거나, 최소한 uv는 계절 기본값 고려.

**F-4. 위치 표기·데이터 소스 불일치 (기지 이슈 재확인)**
- `app/(main)/home/page.tsx:1123` "서울 강남구" 하드코딩 vs 날씨 좌표 37.5665,126.9780(중구·시청)·에어코리아 종로구 측정소(`:390-391`). SPEC.md 버그 현황에 🟡로 등재된 알려진 이슈 — 지표 신뢰성 관점에서 재확인만 기록.

### P3

**F-5. 습도 40% 경계 불일치**
- 시간대 카드: `t.humidity <= 40` warn (`page.tsx:1377`) / 공유 카드 뱃지: `humidity < 40` warn (`recommendation-engine.ts:126`). 정확히 40%일 때 카드는 "건조" 경고, 뱃지는 "적정". 또한 카드가 경고하는 고습(≥80)이 케어 플랜 특이사항(`slotNotables`)에는 없음(여벌 옷 키워드로만 간접 반영).

**F-6. 공유 카드 자외선 뱃지가 순간값 기준**
- `page.tsx:447` `weatherData.uvIndex = u.uvi`(현재 시각) → `buildBadges`의 `uvIndex >= 6` 판정이 아침 공유 시 한낮 피크를 놓쳐 "보통"으로 나감. envSignature(급변 판정)는 hourly 피크를 쓰고 있어(60-61행) 내부 기준과도 다름.

**F-7. 체감온도 공식이 여름에 부적합**
- 서버(`weather/route.ts:221`)·클라이언트(`timeline.ts:179`) 공통 `temp − 0.7 × 풍속` — 겨울 풍속냉각 근사를 여름에도 적용해 폭염일 체감이 실제보다 낮게 표시(31°·풍속 5m/s → 체감 27.5°). 폭염 케어 판단에 과소평가 위험. 기상청 여름 체감온도(습도 기반) 공식 병용 권장.

**F-8. 미세먼지 지표가 PM10 단독**
- `/api/air`는 pm25Grade·khaiGrade를 내려주지만 홈은 `pm10Grade`만 사용(`page.tsx:414`, `timeline.ts:144`). 영유아 건강엔 PM2.5가 더 유의미. `timeline.ts:69` 주석("통합대기 등급")도 실제 입력(pm10)과 불일치.

**F-9. AI 리포트 카드 새로고침·공유 버튼 터치 타겟 32px**
- `page.tsx:1158-1177` `p-2` + 16px 아이콘 = 32px < DESIGN.md 최소 44px (헤더 `headerBtn`은 44px 준수). QA 모드 DESIGN 정합 flag 규정에 따라 기록.

**F-10. SPEC.md P-04 문서 드리프트**
- SPEC의 홈 구성(상태 필, 뱃지 5개 가로 나열, 추천 아이템 카드, hook 19px)이 현재 코드(뱃지는 공유 카드 전용, 추천 아이템 섹션 없음, hook 26px)와 불일치. 기능 작업 전 SPEC 우선 참조 규칙상 갱신 필요.

## 참고 관찰 (문제 아님)

- 초회 렌더에서 1회 `Invalid or unexpected token` pageerror + 스켈레톤 정지가 관찰됐으나 재실행에서 재현 불가 — dev 모드 온디맨드 컴파일/프록시 환경(외부 CDN 폰트 차단) 아티팩트로 추정. 실배포 환경 징후 없음.
- curl로 한글 쿼리를 인코딩 없이 보내면 400이 나는 것은 HTTP 파서 레벨 거부로, 브라우저 fetch(자동 인코딩)에서는 발생하지 않음.
- 강수확률 warn(≥60%)·우산 확정 신호(창 max ≥60% 또는 강수형태)·예비 신호(40~50%) 임계값이 카드·prep·프롬프트(v17) 간 일치함을 확인.

## 결론

빌드·린트·테스트·폴백 경로는 모두 정상이고, 실측 경로의 지표 매핑·임계값·캐시·경합 방어도 견고하다. 다만 **꽃가루 지표는 잡초류 미조회로 8월부터 사실상 무력화될 예정(P1)**이며, **API 장애 시 mock/결측 값이 실측처럼 보이는 신뢰 문제(P2 ×2)**가 있다. P1·P2는 `/qa`(수정 포함) 또는 개별 작업으로 처리 권장.
