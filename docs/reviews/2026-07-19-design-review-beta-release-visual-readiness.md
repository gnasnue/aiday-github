# 베타 배포 전 UI/UX 시각 완성도 감사

## 결론

**순수 시각 품질은 베타 배포 가능한 수준이다.** 웜 뉴트럴 배경, 흰 카드, 제한된 오렌지, 20px 카드 라운드, 공용 헤더·BottomNav가 전 화면에서 안정적으로 이어진다. 특히 홈은 첫 화면 안에 `오늘의 결론 → 오늘 챙길 것 → 시간대별 환경의 시작`이 들어와 핵심 판단이 잘 보인다.

다만 **현재 상태 그대로의 공개 베타는 조건부 No-Go**다. 이유는 장식이나 심미성이 아니라, 화면이 실제 데이터·개인화처럼 보이면서 서로 모순되는 2개의 신뢰 문제다. 아래 P0를 먼저 제거한 뒤 배포하는 것을 권장한다.

## 감사 범위와 방법

- 390 × 844px 모바일 뷰에서 `/`, `/onboarding`, `/home`, `/env`, `/outfit`, `/tips`, `/me` 실제 렌더 확인
- 로딩 직후와 데이터 정착 후 화면을 각각 확인
- DOM 기반 스크롤 높이·가로 넘침·인터랙션 터치 영역 실측
- `DESIGN.md`의 타이포, 색, 카드, 44px 터치 타겟, 아이콘 규칙과 코드 교차 감사
- 주요 페이지 스크롤 높이: 랜딩 2870px / 홈 1555px / 환경 2692px / 옷차림 2208px / 건강팁 3158px / 마이 1158px

## P0 — 배포 전 반드시 제거

### P0-1. 건강팁이 mock 데이터를 “오늘의 맞춤 가이드”로 표시한다

동일한 사용자 세션에서 환경정보는 `PM10 6`, `PM2.5 6`, `습도 68%`, `꽃가루 예보 기간 아님`으로 표시됐지만, 건강팁은 `PM10 62`, `PM2.5 28`, `습도 38%`, `참나무 꽃가루 매우높음`을 근거로 카드를 노출했다.

- 코드 근거: `app/(main)/tips/page.tsx:22-30`의 고정 `env` 객체
- 오인 강화: `app/(main)/tips/page.tsx:286`의 “지우를 위한 오늘의 가이드”
- UX 영향: 부모는 어느 화면이 맞는지 판단할 수 없고, 아동 건강 조언 전체를 신뢰하지 않게 된다.
- 내일 배포용 최소 수정: 실데이터 연동이 어렵다면 화면명을 **“아이 건강 정보 라이브러리”**로 바꾸고 `오늘`, 환경 수치, 개인화 표현을 제거한다. 고정 환경값으로 생성되는 주의 카드는 숨기고 일반 가이드와 카테고리 탐색만 남긴다.
- 정식 수정: `/env`와 같은 실시간 데이터 소스를 공유하고, 데이터 생성 시각·출처·프로필 조건을 함께 표시한다.

### P0-2. 랜딩이 아직 없는 알림 기능을 현재 제공 기능처럼 약속한다

랜딩의 네 번째 기능은 “전날 밤 · 아침 준비 전, 굳이 앱을 열지 않아도 … 미리 받아볼 수 있어요”라고 단정한다. 현재 제품 결정 문서상 알림/PWA는 미구현 범위다.

- 코드 근거: `app/page.tsx:17`
- UX 영향: 가입 직후 가장 기대한 기능을 찾지 못해 첫 세션 이탈과 베타 피드백 왜곡이 생긴다.
- 내일 배포용 최소 수정: 해당 기능 카드를 제거하거나 **“베타 이후 제공 예정”**으로 명시한다.
- 추가 확인: `app/page.tsx:113-132`의 후기 3건이 실제 인터뷰/테스트 참여자 발언이 아니라면 배포 전 제거한다. 유지하려면 “사전 인터뷰” 등 출처 성격을 명확히 표시한다.

## P1 — 내일 배포 전 함께 고치면 좋은 항목

### P1-1. 핵심 보조 액션의 터치 영역이 44px보다 작다

실측 결과:

| 화면 | 요소 | 실측 |
|---|---|---:|
| 공통 | 로고 홈 링크 | 144 × 30px |
| 홈 | 리포트 새로고침 / 공유 | 32 × 32px |
| 홈 | 자세히 | 48 × 33px |
| 환경 | 위치 선택 | 55 × 16px |
| 환경 | 기상청 출처 | 55 × 16px |
| 건강팁 | 프로필 수정 | 21 × 16px |
| 마이 | 편집 | 높이 36px |
| 마이 | 삭제 | 36 × 36px |
| 온보딩 | 뒤로가기 | 36 × 36px |
| 온보딩 | 나중에 이어서 하기 | 89 × 16px |
| 랜딩 | 먼저 둘러볼게요 | 105 × 20px |

- 코드 예: `components/Logo.tsx:37-45`, `app/(main)/home/page.tsx:1295,1303`, `app/(main)/me/page.tsx:116,122`, `app/onboarding/page.tsx:599,604,647`
- 개선: 시각 크기는 유지하되 컨테이너에 `min-h-11 min-w-11`을 적용한다. 텍스트 링크도 행 전체를 44px hit area로 만든다.

### P1-2. 홈 AI 리포트 헤더의 메타가 잘린다

390px 실제 화면에서 `AI 리포트 · 기본 추천 · 7월 19일 (일) 11…`처럼 생성 시각이 말줄임된다. 같은 줄의 새로고침·공유 아이콘이 64px를 차지해 신뢰 메타와 경쟁한다.

- 코드 근거: `app/(main)/home/page.tsx:1284-1305`
- 개선: 첫 줄은 `AI 리포트 + 갱신 시각`만 남기고 액션은 다음 줄 또는 overflow 메뉴로 이동한다. 44px 터치 타겟 확대와 동시에 해결해야 한다.

### P1-3. 10~11px 텍스트가 정보 신뢰와 가독성을 떨어뜨린다

- 홈 데이터 출처/trust line: `11px + muted-foreground/70`로 실제 화면에서 매우 옅다 (`home/page.tsx:1470`).
- 홈 케어 상태 `기본/지금/곧/다음`: 10px (`home/page.tsx:1607-1617`).
- 옷차림 수량·AI 배지: 10px (`outfit/page.tsx:420,456`).
- DESIGN.md 기준: 11px는 eyebrow 전용 최저값, 일반 캡션은 13px.
- 개선: trust line은 13px·충분한 대비로 올리고, 상태/수량은 최소 11~13px로 통일한다. 공간이 모자라면 글자를 줄이지 말고 정보를 줄인다.

### P1-4. 로딩 중 첫 화면이 지나치게 비어 보인다

홈은 데이터 정착까지 약 8초 동안 AI 카드와 시간대 카드가 거의 무채색 스켈레톤으로만 보였다. 구조는 안정적이지만, 처음 보는 사용자는 앱이 멈춘 것으로 오해할 수 있다.

- 현재 장점: 레이아웃 이동은 거의 없어 CLS는 양호함.
- 개선: AI 카드 상단 라벨을 로딩 중에도 유지하고 `오늘 환경을 분석하고 있어요` 한 줄을 넣는다. 2초 이상이면 데이터별 진행 상태나 재시도 안내를 노출한다.

### P1-5. 옷차림의 결론과 목록이 완전히 맞물리지 않는다

상단 조언은 “얇은 아우터”를 권하지만 첫 추천 목록에는 이너·하의·액세서리만 있고 아우터가 보이지 않는다. 첫 화면에서 사용자는 조언을 읽은 뒤 무엇을 선택해야 할지 다시 해석해야 한다.

- 개선: 상단 한 줄 결론에 등장한 품목을 추천 목록의 첫 그룹으로 보장한다. `악세사리` 표기는 `액세서리`로 수정한다.

## P2 — 베타 중 빠르게 다듬기

### P2-1. 건강팁 기본 화면이 너무 길다

`전체`가 기본이라 3158px 길이의 카드 5개가 한꺼번에 열린다. 아침에 훑는 앱의 리듬과 맞지 않는다.

- 개선: 오늘 관련성이 가장 높은 1~2개만 펼치고 나머지는 접는다. 출처 목록도 기본 접힘으로 두되, 출처가 있다는 신호는 카드 헤더에 유지한다.

### P2-2. 환경정보 하단의 주간·나들이 정보가 핵심 판단을 희석한다

환경 화면은 2692px로 길다. 첫 화면의 현재 날씨·야외활동 지수·맞춤 인사이트는 매우 좋지만, 주간 날씨와 두 날짜의 나들이 장소가 이어져 환경 판단 화면에서 탐색 피드로 성격이 바뀐다.

- 개선: 이번 주말 나들이는 요약 카드 1개 + “자세히”로 축약한다. 베타 수요 프로브는 유지할 수 있다.

### P2-3. BottomNav 높이가 디자인 기준보다 작다

`components/BottomNav.tsx:25-43`은 실제 높이 약 56~57px다. DESIGN.md 기준은 64px이다. 터치 타겟 자체는 56px로 충분하지만 아이콘·레이블이 화면 하단에 다소 붙어 보인다.

- 개선: 64px 표준과 safe-area를 명시하고 상하 여백을 재배분한다.

### P2-4. 공유 이미지에는 raw 이모지가 다시 등장한다

일반 UI는 Lucide/LineIcon으로 잘 정리됐지만, 공유용 숨은 카드의 체크리스트에는 `☂️`, `🧴`, `🧢`, `💊` 같은 OS 이모지가 렌더된다. 공유 이미지는 외부에서 브랜드를 대표하므로 DESIGN.md의 이모지 금지 원칙을 적용하는 편이 좋다.

- 개선: 공유 카드도 동일한 벡터 아이콘 또는 자체 SVG로 렌더한다.

## 화면별 평가

### 랜딩

- 강점: 첫 화면에서 문제·가치·CTA가 명확하고, 오렌지 CTA 대비가 좋다. 다음 섹션의 시작이 보여 스크롤 유도도 자연스럽다.
- 개선: P0의 미구현 알림 약속, 후기 출처, 20px 높이의 둘러보기 링크.

### 온보딩

- 강점: 1/5 진행률, 질문 카드, 입력, 하단 고정 CTA의 흐름이 가장 안정적이다. 390px 한 화면에 한 단계가 정확히 들어온다.
- 개선: 상단/하단 보조 액션 터치 영역. 입력 focus ring은 접근성 측면에서 양호하다.

### 홈

- 강점: 데이터 정착 후 844px 첫 화면에 AI 결론, 4개 체크리스트, 다음 섹션 제목까지 들어온다. 현재 앱에서 가장 glanceable한 화면이다.
- 개선: 메타 잘림, 32px 도구 버튼, 11px 저대비 trust line, 로딩 피드백.

### 환경정보

- 강점: 현재 날씨 → 야외활동 지수 → 개인화 경고의 위계가 명확하다. 상태색도 good/warn 의미에 맞게 쓰였다.
- 개선: 16px 높이 위치·출처 링크, 하단 콘텐츠 길이.

### 옷차림

- 강점: 28° 현재 조건과 아이 체질 조언, 추천 그룹이 첫 화면에서 빠르게 연결된다. 카드 밀도도 편안하다.
- 개선: 10px 배지, 조언과 아이템 불일치, `AI코디 추천`의 작은 빨간 라벨.

### 건강팁

- 강점: 출처와 의료 면책, 카테고리 필터, 경고 상태가 시각적으로 명확하다.
- 개선: mock 데이터 오인(P0), 과도한 기본 길이, 16px 수정 링크.

### 마이

- 강점: 프로필 카드 2개와 선택 상태, 핵심 정보, 계정 메뉴의 구조가 가장 예측 가능하다.
- 개선: 편집·삭제 36px 터치 타겟. 삭제는 위험 액션이므로 특히 44px와 명확한 pressed 상태가 필요하다.

## 내일 배포 전 권장 순서

1. 건강팁의 mock 환경값·“오늘 맞춤” 오인 제거
2. 랜딩의 미구현 알림 약속 제거, 후기 출처 확인
3. 홈·마이·온보딩의 44px 미만 핵심 액션 확대
4. 홈 리포트 헤더 메타 잘림과 trust line 가독성 수정
5. 옷차림 조언과 추천 아이템 일치 확인
6. 가능하면 홈 로딩 문구 추가

## 최종 판단

**P0 두 건을 제거하면 베타 배포를 권장한다.** 현재 화면은 이미 “정돈된 모바일 육아 앱”으로 보이며, 색이나 그림자를 더 추가할 필요는 없다. 내일의 핵심은 미세한 장식이 아니라 **화면이 약속하는 내용과 실제 데이터가 정확히 일치하게 만드는 것**, 그리고 **핵심 보조 액션을 44px로 보장하는 것**이다.
