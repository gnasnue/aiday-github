# Claude Design 감사 × Codex 감사 교차 검증

## 결론

두 감사는 핵심 진단에서 **높게 일치한다**. 특히 건강팁 mock 데이터, 10~12px 소형 텍스트, 낮은 대비의 보조 정보, 44px 미만 터치 타겟, 화면의 정보 중복과 가짜 affordance를 독립적으로 같은 문제로 찾았다.

Claude 감사에서만 명시적으로 발견한 내용 중 **현재 코드로 재검증되어 수용해야 할 항목도 있다.** 가장 중요한 추가 발견은 `/env`의 위치 기준지 분리, 상태 게이지의 브랜드 오렌지 오용, 13px 흰색 CTA의 대비 위반이다.

단, Claude 보고서의 홈 스크린샷은 2026-07-17 상태다. 2026-07-19 현재 코드·실제 렌더와 달라진 부분은 그대로 채택하지 않았다.

## 2. Claude가 추가로 발견했고 수용해야 하는 항목

### A-1. `/env`가 홈과 다른 위치 기준지를 사용한다 — 수용, 배포 전 우선 수정

- 홈: `aiday:location:v1`과 실제 위치를 이용해 위도·경도·측정소를 함께 갱신 (`home/page.tsx:227-252, 413-414, 824-842`).
- 환경정보: 서울시청 좌표와 종로구 측정소를 고정 호출 (`env/page.tsx:148-155`). 위치 버튼은 “준비 중” toast만 표시 (`:370`).
- 판단: 사용자가 홈을 강남구 등으로 바꿔도 환경 상세 화면은 서울시청/종로구를 보여줄 수 있다. `/env`는 홈 판단의 근거 화면이므로 같은 위치 상태를 공유해야 한다.
- 우선순위: **P1, 위치 변경을 베타에 노출한다면 P0에 준함.**

### A-2. 상태 게이지에 브랜드 `primary`를 사용하는 문제 — 수용

- `env/page.tsx:415-421`: 야외활동 지수 “보통”에 `bg-primary`.
- `env/page.tsx:555-565`: UV 데이터 없음 또는 중간 구간에 `bg-primary`.
- DESIGN.md는 게이지를 상태색 fill로 규정하고 solid primary는 브랜드/CTA 전용으로 제한한다.
- 개선: 보통은 `status-neutral`, 경고는 `status-warn`, 좋음은 `status-good`. 데이터 없음은 fill 0 또는 neutral placeholder로 처리한다.

### A-3. `text-red-500` 비토큰 색상 — 수용

- `outfit/page.tsx:456`의 `AI코디 추천` 배지는 `text-red-500`을 사용한다.
- 현재 웜 팔레트와 의미 토큰에 속하지 않고, 경고가 아닌 AI 추천을 위험 신호처럼 보이게 한다.
- 개선: 정보성 AI 라벨이면 `bg-primary-tint text-accent`, 실험/베타 라벨이면 neutral 계열을 사용한다.

### A-4. 13px 흰색 CTA의 대비 규칙 위반 — 수용

- `env/page.tsx:745-748`의 “더 보고 싶어요”는 `bg-primary` 위 `13px semibold` 흰색이다.
- DESIGN.md는 primary 위 흰색 텍스트를 17px bold 이상으로 제한한다.
- 개선: CTA 표준인 17px/700으로 올리거나, 작은 버튼을 유지하려면 `bg-primary-tint text-accent`로 바꾼다.

### A-5. 케어 플랜 카드 외곽 보더 — 문제는 수용, 해결책은 수정 채택

- `home/page.tsx:1595-1599`에서 모든 케어 카드에 외곽 border를 사용하고 현재 슬롯만 primary border를 사용한다.
- v3의 카드 외곽 보더 금지와 충돌한다.
- 권장안: 일반 카드는 보더를 제거하고, 현재 슬롯은 이미 존재하는 오렌지 도트·`지금` 라벨·아주 옅은 `primary-tint` 중 2개 이하로 강조한다.
- Claude의 S-3처럼 카드 보더 예외를 새로 허용하는 것보다는 기존 문법을 지키는 편이 더 절제되고 일관적이다.

### A-6. tips에서 accent를 상태·면·불릿에 반복 사용 — 수용

- 디스클레이머: `border-accent/20 bg-accent/5` (`tips/page.tsx:304`).
- 프로필 매칭 라벨: `bg-accent/10` (`:372`).
- 권고 불릿: `bg-accent` (`:387`).
- 한 카드 안에 아이콘 상태색, 카테고리, 심각도, 매칭 라벨, 오렌지 불릿까지 색 신호가 겹친다는 Claude의 R-4는 실제 화면에서도 정확하다.
- 개선: 의료 면책은 `status-info`, 카드당 대표 상태색은 심각도 1개만 유지, 불릿은 foreground/muted로 낮춘다.

### A-7. 화면별 정보의 정본(canonical surface) 원칙 — 방향 수용

Claude 제안인 `home=판단 요약 / env=환경 근거 / outfit=의류 / tips=건강 행동 근거 / me=프로필 정본`은 정보구조를 정리하는 데 유효하다.

구체적으로 수용할 부분:

- 보호장구·준비물의 최종 체크 정본은 home.
- outfit은 의류·코디 중심으로 제한.
- env는 상태와 짧은 행동 한 줄, 긴 건강 행동 설명은 tips로 연결.
- 프로필 상세 정본은 me, tips의 프로필 카드는 매칭 근거 한 줄로 축소.

다만 home의 체크리스트와 시간대별 케어 플랜은 각각 `무엇을 챙길지`와 `언제 쓸지` 역할이 달라 완전 중복 제거 대상은 아니다.

### A-8. 디자인 감사 스킬 자체의 기준값이 오래됨 — 수용

Claude는 감사 지시문의 `primary #F5A623`, “2xl~xs”가 v2라고 지적했다. 실제 `DESIGN.md` v3의 primary는 `#F97316`이며 7단 스케일을 사용한다. 향후 감사 혼선을 막기 위해 `.agents/skills/design-review/SKILL.md` 체크리스트를 v3와 맞춰야 한다.

## 3. 부분 수용 또는 보류할 Claude 지적

### B-1. “홈 체크리스트가 fold에서 잘린다” — 현재는 수용하지 않음

Claude의 근거 이미지는 2026-07-17 화면이다. 2026-07-19 실제 390×844 렌더에서는 AI 결론과 4개 체크리스트가 모두 첫 화면에 들어오고, 다음 `시간대별 환경` 제목도 보였다. 현재 홈 히어로 높이는 약 552px, 카드 하단은 y≈689였다.

따라서 체크 아이콘 컨테이너를 제거해 행을 압축할 긴급 근거는 현재 없다. 다만 장래 체크 항목이 5개 이상으로 늘어날 때는 다시 검증해야 한다.

### B-2. 홈에 옷차림 한 줄을 추가 — 전략 검토 대상, 즉시 수용 아님

제품의 핵심 판단에 옷차림이 포함되므로 제안 자체는 타당하다. 그러나 현재 첫 화면은 이미 결론과 4개 준비물로 채워져 있다. 행을 추가하면 다시 밀도가 높아질 수 있다.

먼저 홈 AI hook/체크리스트가 옷차림 결론을 포함하도록 데이터 계약을 정리하고, 베타에서 outfit 탭 진입률을 본 뒤 결정하는 편이 안전하다.

### B-3. 모든 일반 카드를 p-4로 문서화 — 원칙만 수용

현행 DESIGN.md의 모든 L1 `p-5` 규칙과 실제 코드가 어긋난다는 지적은 맞다. 그러나 3열 대기질 타일 같은 compact metric card까지 p-4로 통일하면 밀도가 깨진다.

권장 문서 개정:

- Hero/L2: p-5
- Standard/L1: p-4 또는 p-5
- Compact metric tile: p-3

컴포넌트 종류별 문법을 명시해야 하며, “일반은 전부 p-4”로 단순화하지 않는다.

### B-4. faint 토큰 자체를 전역 심화 — 사용 제한안을 우선

`#9C938A`가 작은 본문성 정보에 쓰이면 대비가 부족하다는 진단은 맞다. 하지만 placeholder·비활성 상태까지 전부 4.5:1로 올릴 필요는 없다.

먼저 `faint는 placeholder·비활성·장식 전용`, 날짜·출처·시간처럼 읽어야 하는 정보는 `muted-foreground` 이상이라는 사용 규칙을 추가한다. 그래도 필요한 곳만 토큰을 심화한다.

### B-5. 크림 헤더 전체 제거 — 단순화는 동의, 제거는 보류

Codex 실측에서도 홈 리포트 메타가 말줄임되므로 과밀 진단은 맞다. 그러나 크림 띠는 화면당 하나뿐인 히어로를 식별하는 유효한 시각 신호다.

우선 `AI 리포트 + 갱신 시각`만 남기고 새로고침·공유를 다른 위치로 옮긴다. 이후에도 과밀하면 크림 헤더 제거를 검토한다.

## 4. Claude 보고서에 없지만 Codex 감사에서 유지해야 할 항목

Claude 감사 범위가 5개 메인 탭 중심이어서 다음 항목은 빠졌다.

- 랜딩의 미구현 알림 약속: `app/page.tsx:17` — 공개 베타 전 제거/예정 표기.
- 랜딩 후기의 실제 출처 확인: 실제 인터뷰가 아니면 제거 또는 성격 명시.
- 홈 로딩 상태가 장시간 무채색 skeleton으로만 보이는 문제.
- 옷차림 상단 조언의 “얇은 아우터”와 추천 목록 불일치, `악세사리` 표기.
- 공유 이미지에서 raw 이모지가 다시 렌더되는 문제.
- 랜딩·온보딩·공통 로고까지 포함한 44px 미만 터치 타겟. Claude는 me/env 일부만 찾았다.
- BottomNav 실제 높이 56~57px와 DESIGN.md 64px 기준 불일치.

## 5. 통합 배포 우선순위

### 배포 전 필수

1. 건강팁 mock 데이터와 “오늘의 맞춤” 표현 제거 또는 실데이터 연동.
2. env가 home과 동일한 위치 기준지·측정소를 공유하도록 수정.
3. 랜딩의 미구현 알림 약속 제거, 후기 출처 확인.

### 가능하면 배포 전

4. 핵심 액션 44px 터치 타겟 보장.
5. 홈 리포트 메타/도구 과밀 해소와 trust line 대비 개선.
6. env 게이지 상태색, 작은 흰 CTA, outfit `text-red-500` 정리.
7. tips 카드의 색 신호를 심각도 하나로 축소.

### 베타 중 후속

8. 화면별 정본 원칙에 따라 준비물·환경·건강 행동 중복 정리.
9. 케어 플랜 카드 보더 제거와 카드 padding variant 문서화.
10. DESIGN.md와 design-review 스킬의 토큰·타입 기준 동기화.

## 최종 판단

Claude 보고서는 전반적으로 정확하며, Codex 감사의 결론을 강화한다. 특히 `/env` 위치 기준 불일치와 색상 의미/대비 문제는 Codex가 첫 감사에서 충분히 강조하지 못한 **명백하게 수용할 추가 발견**이다.

다만 오래된 홈 캡처를 근거로 한 fold 판단과 모든 카드 패딩·보더를 단일 규칙으로 해석한 부분은 현재 화면과 컴포넌트 역할을 기준으로 조정해서 채택해야 한다.
