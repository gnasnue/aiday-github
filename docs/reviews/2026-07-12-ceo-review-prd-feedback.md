# ChatGPT 피드백에 대한 PRD 반영 검토

## 결론

PRD v2.4는 안전·비용 보호, 최소 계측의 1주차 이동, 수동 컨시어지 테스트, 민감정보 동의, 카카오 착수 게이트를 이미 반영했다. 따라서 피드백을 전부 다시 쓰기보다, **사용자 행동 검증이 구현 범위를 실제로 통제하도록** PRD를 보완해야 한다.

현재 6주 P0는 브리핑 가치가 통과하기 전에 PWA·웹 푸시 2종을 구현하도록 되어 있다. 수동 컨시어지 테스트가 '병행 트랙'에 머물러 있어 결과가 PWA 착수를 막지 못한다. 이 상태로는 문서의 검증 선언과 일정이 충돌한다.

## 반영 완료 또는 충분히 반영된 항목

- `daily_briefings` 단일 원본, 골든 케이스 평가, 안전 필터, `/api/report` 레이트리밋은 PRD v2.4 P0에 명시됐다.
- PostHog 최소 계측을 1주차에 배치했고, 체크·해제와 저녁 결과 피드백을 운영 DB 원본으로 저장하도록 정의했다.
- 게스트 데모 프로필의 '예시' 표기, 더미 추천 상품 숨김, 민감정보 별도 동의와 처리방침은 P0 신뢰성 정합에 포함됐다.
- 컨시어지 테스트와 공개 베타 Go/No-go 기준이 추가됐다.
- 카카오 채널은 웹 푸시 퍼널의 iOS 도달 병목이 확인될 때만 착수하도록 좁혔다.

## PRD에 추가 또는 수정해야 할 항목

### P0-1. 연구 근거를 가설과 분리

PRD의 FGI 수치(76.4%, 88.2%, 82.4%, 89%, 76.5%)에는 N, n, 정확한 질문, 조사 방식, 모집 방식이 없다. '소규모 FGI'라는 설명만으로는 소수점 수치를 재검증할 수 없다.

- PRD에는 수치를 **사용자 자기보고·탐색 근거**로만 표시하고, H1~H6 가설 표를 추가한다.
- `docs/validation/RESEARCH-EVIDENCE.md`를 근거 원장으로 만들고 모든 비율에 n/N·질문·조사 방법·반대 증거를 기록한다.
- 원장이 준비되기 전에는 공개 PRD/랜딩에서 정확한 비율을 제거하거나 '소규모 자체 인터뷰에서 확인된 경향'으로 낮춘다.
- 합성 페르소나 서연은 '대표 검증 시나리오'로 표기한다. `docs/문제정의-프레임워크-v2.md`의 '반박 불가능한 증거' 표현도 실제 관찰 전제의 가설 언어로 바꾼다.

### P0-2. 검증 게이트를 PWA보다 앞에 둠

PRD Phase 4는 PWA·웹 푸시 2종을 완료 조건으로 둔다. 반면 제품 결정 문서는 알림 없이도 아침 판단 가치를 측정할 수 있다고 한다. 둘 중 후자가 최초 베타의 더 작은 실험 범위에 맞다.

- 1~2주차에 **8~15가구, 7일 수동 브리핑 테스트**를 먼저 실행한다.
- 테스트 프로토콜은 사전 인터뷰, 설명 없는 과제 수행, 매일 확인/실행/타 앱 재확인/저녁 결과/다음 주 수신 의향 기록을 포함한다.
- PRD의 PWA·웹 푸시·전날 밤 알림은 검증 게이트 통과 뒤 착수하는 fast-follow로 옮긴다. 카카오와 PWA의 각각의 기술 착수 게이트가 아니라, 그보다 앞선 '브리핑 가치·반복 수요' 게이트가 필요하다.
- Go/No-go에는 문제 반복성, 과제 이해, 추천 실제 사용, 타 앱 재확인, 지속 수신 의향, 심각한 안전 문제 0건을 구분해 기록한다.

### P0-3. MVP의 단일 루프를 화면·온보딩·내비게이션에 반영

PRD 화면 정의에는 아직 5개 바텀 탭과 캐릭터 종합 솔루션이 남아 있고, 온보딩 완료율도 7단계 기준이다. 이는 '30초 안에 오늘 행동 3개를 결정·확인'하는 베타 목적보다 넓다.

- 베타 핵심 흐름을 `랜딩 → 예시 브리핑 → 최소 온보딩 → 개인화 브리핑 → 행동 체크 → 도움 여부`로 고정한다.
- 온보딩 필수 항목을 별명·연령대·특성·오늘 일정·지역의 4단계 이하로 축소한다. 정확한 생년월일, 성별, 알림 설정은 후순위이며 건강 특성은 선택 입력으로 둔다.
- 최상위 내비게이션은 '오늘 / 내 아이'로 축소하고, 환경·옷차림·건강팁은 브리핑 상세의 근거 화면으로 이동한다.
- 캐릭터 종합 솔루션은 AI 브리핑과 결론이 겹치므로 최초 베타에서는 숨긴다. 추천 상품 숨김은 유지한다.

### P0-4. 위치 정합을 신뢰성 차단 조건으로 승격

홈은 '서울 강남구'를 표시하지만 실제 요청은 서울시청 좌표(37.5665, 126.9780)와 종로구 측정소를 쓴다. 환경 입력이 핵심 판단의 근거이므로 이는 단순 UX 문제가 아니라 잘못된 브리핑 위험이다.

- 최소 온보딩의 지역 선택값 하나를 날씨 좌표와 대기질 측정소에 공통 매핑하고, 표시 지역과 API 입력이 일치해야 한다.
- 자동 위치 권한은 후순위로 두되, 선택 가능한 지역·좌표·측정소의 관리 테이블과 fallback 규칙을 PRD 수락 기준에 명시한다.

### P1. 랜딩 후기 출처 상태 표기

현재 랜딩의 '부모님들의 이야기'는 코드상 고정 문자열이며, 실제 원문·편집·합성 여부를 확인할 근거가 없다.

- 게시 동의받은 실제 발언이면 시점·대상·편집 여부를 표시한다.
- 합성 또는 예시 문구면 섹션을 '이런 순간에 사용할 수 있어요'로 바꾸거나 베타 전까지 숨긴다.
