# Design Review — 시각적 정합성 감사

구현된 화면을 DESIGN.md 기준으로 감사한다. (구현 전 계획 검토는 /plan-design-review.)

## 진행 순서

1. **DESIGN.md 전체를 읽고** 핵심 기준을 체크리스트로 뽑는다:

   | 항목 | 기준값 |
   |------|--------|
   | 최소 터치 타겟 | 44px × 44px |
   | Primary color | `#F5A623` |
   | Font | Pretendard Variable, 정의된 스케일(2xl~xs)만 |
   | Base spacing | 4px 배수 |
   | 아이콘 | Lucide React (OS 이모지 금지) |
   | 프레임 | 390px 고정 + BottomNav |
   | 장식 | 색상·그림자만 (CharacterReport 캐릭터가 유일 예외) |

2. **스크린샷 + 코드 병행 감사**: 가능하면 `npm run dev` 후 화면을 캡처해 시각 확인하고, 각 화면의 코드(`app/(main)/*`, `components/*`)를 정적 분석한다. 하드코딩된 hex 색상, 임의 폰트 크기, 인라인 이모지를 grep으로 찾는다.
3. **Findings 정리**: 심각도(P0~P3)와 파일:라인, DESIGN.md 근거 조항, 수정 방안을 기록한다.

## 산출물

리포트를 `docs/reviews/YYYY-MM-DD-design-review-<주제>.md`로 저장한다. 서두에 메타데이터를 포함한다:

```
> Generated by `/design-review` on YYYY-MM-DD
> Branch: `<branch>`
> Repo: gnasnue/aiday-github
> Design Authority: `DESIGN.md`
```

수정은 사용자 승인 후 진행한다. 승인되면 수정 후 해당 화면을 다시 확인하고 CHANGELOG.md에 기록한다.
