# Investigate — 버그 조사

버그의 **근본 원인**을 찾아 보고한다. 원인이 확정되기 전에는 수정하지 않는다 — 추측성 수정 금지.

## 진행 순서

1. **재현 조건 확정**: 어떤 입력/시간대/환경에서 발생하는가. 재현이 안 되면 그 사실부터 보고한다.
2. **증거 수집**:
   - 관련 코드 경로 추적 (증상 → API 라우트 → lib → 외부 API)
   - `npm run dev`로 실제 재현 시도, 브라우저 콘솔·서버 로그 확인
   - `git log` 로 해당 코드의 최근 변경 이력 확인 (회귀인지 판단)
3. **아이데이 단골 원인 체크리스트**:
   - 외부 API 스펙 변경/오퍼레이션명 오류 (꽃가루 V3 API 404 전례)
   - 시간대 의존 데이터 (자외선 지수는 KST 06시 발행 — 그 전엔 어제 데이터 fallback 필요)
   - 캐시 키 버전 불일치로 구형 캐시가 반환되는 경우
   - Anthropic API 파라미터 범위 초과 (temperature 등)
   - 환경 변수 누락 (`.env.example` 대조)
   - Supabase RLS 정책으로 인한 빈 쿼리 결과
4. **원인 보고**: 원인, 근거(파일:라인), 영향 범위, 수정 방안을 제시하고 멈춘다. 수정은 사용자 승인 후 진행한다.

## 수정 시 규칙 (승인 후)

- 수정과 함께 같은 계열의 잠재 버그가 코드베이스에 더 있는지 grep으로 확인한다.
- CHANGELOG.md의 `### Fixed` 항목에 기록한다 (원인까지 한 줄로).
