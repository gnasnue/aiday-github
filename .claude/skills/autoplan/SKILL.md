# Autoplan — 풀 리뷰 파이프라인

하나의 계획/변경사항에 대해 세 관점의 리뷰를 순차 실행하고 통합 결론을 낸다.

## 실행 순서

1. **/plan-ceo-review** — 전략·스코프. 판정이 **STOP**이면 여기서 파이프라인을 중단하고 사유를 보고한다. **CUT**이면 축소된 스코프를 기준으로 다음 단계를 진행한다.
2. **/plan-eng-review** — 아키텍처·기술. P0(BLOCKER)이 나오면 해결 방안을 명시한 뒤 진행한다.
3. **/plan-design-review** — 디자인 시스템 정합성. (UI 변경이 없는 작업이면 이 단계는 건너뛰고 사유를 기록한다.)

각 단계는 해당 스킬의 SKILL.md 절차와 산출물 형식을 그대로 따른다.

## 통합 결론

세 리뷰가 끝나면 통합 요약을 제시한다:

- **최종 판정**: PROCEED / HOLD SCOPE / CUT / STOP (가장 보수적인 판정을 따른다)
- **착수 전 필수 수정** (eng P0·P1, design 위반 항목)
- **확정된 스코프** (CEO 리뷰에서 잘라낸 항목 명시)
- 각 단계 리포트 링크 (`docs/reviews/`)

## 규칙

- 리뷰 간 결론이 충돌하면 숨기지 말고 충돌 지점을 명시한다 (예: CEO는 CUT, Eng는 확장 필요).
- 파이프라인 전체가 리뷰다 — 코드 수정은 하지 않는다.
